# 주비 질문 엔진 — 2026-11-04

## 해결할 문제
종목을 보고 “왜 이렇게 떨어져요?”라고 물었을 때, 가격만 다시 읽거나 일반론을 내놓는 대신 해당 종목·기간·시장 자료를 연결한다. 이어지는 질문에서도 앞선 질문의 뜻을 유지한다. 계좌 보유정보는 자동 전송하지 않는다.

## 요청 처리
1. 기존 인증·성인 AI 동의·요청 제한·일일 횟수·월 비용 제한을 통과한다.
2. 질문(600자), 선택 종목 또는 한국/미국 시장, 비교 기간(최근 1/5/20 거래일), 최근 대화 3개를 검증한다. 종목을 바꾸면 이전 대화를 가져오지 않는다. 이전 AI 문장은 사실 근거로 취급하지 않는다.
3. 가격·뉴스·발표와 관련된 질문 또는 그 후속 질문에만 공개 시장 자료를 수집한다. 회사 제품/용어 질문은 기존 공개 사업/상품/용어 자료를 사용한다.
4. 서버가 공개 시세를 받아 종가 대비 변동률을 계산한다. 비교 시작일·마지막 거래일·통화·가격 시각이 맞는 시장/업종 자료만 비교한다. 반도체는 넓은 기술주 분류보다 반도체 묶음을 우선한다. 한국 종목은 소속 시장과 비교하며 업종 비교가 없으면 미확인으로 남긴다.
5. 마지막 거래일의 최저·최고 가격도 전일 종가와 비교한다. 장중 급락 후 회복을 종가 상승만으로 부정하지 않는다. 최저가 전일 종가보다 높으면 하락이라고 설명하지 않는다. 고점과 저점의 선후 관계/최대 낙폭은 일별 OHLC로 추측하지 않는다.
6. 회사 뉴스 제목, 기존 시장 감시가 수집한 시장/업종 기사 제목, 공개 승인을 거친 기업/금리 자료를 연결한다. 가격 확인 후 나온 같은 거래일의 보도는 따로 표시한다. 다음 거래일 기사를 앞선 거래일의 원인으로 쓰지 않는다.
7. 최신 원인·뉴스 질문에만 하이쿠로 공개 기사 검색(최대 1번)·원문 열기(최대 2번)를 요청한다. 공개 종목명·시장·기간만 검색하며 개인 질문·대화는 검색어에 포함하지 않는다. 답변은 별도의 하이쿠 1회로 생성한다. 근거 설명에는 서버가 준 출처 ID만 허용한다. 기사 제목만 있는 것은 본문/사건/원인 검증과 구분한다. 영향 관계는 조건부 설명이며 실제 원인으로 확정하지 않는다.
8. 길이·형식·출처 ID·등락 부호·매매 지시를 검사한 다음 이용 횟수를 기록한다. 자료를 하나도 못 받은 시장 질문은 AI 호출 전에 중단한다. 응답 검증 실패는 사용자 횟수를 차감하지 않지만 이미 발생한 제공자 비용은 기록한다.
9. 답변 아래에는 코드가 계산한 비교표, 근거 링크, 자료 시각과 한계, 이어서 물을 질문을 표시한다. 후속 버튼은 입력창만 채우며 전송 전에는 비용이 발생하지 않는다.

## 지속 사용과 비용
- 특정 회사별 화면을 별도로 만들지 않고 같은 입력·수집·계산·검증·표시 구조를 쓴다.
- 공개 근거만 프로세스 메모리에 최대 200개/60초 보관하고 동시 요청을 합친다. 서버 인스턴스 간 영속 캐시를 보장하지 않는다.
- 회사/시장/업종 수집은 병렬로 실행하고 시간 제한을 둔다. 별도 예약 작업을 추가하지 않는다.
- 대화는 화면에 최대 4개, 다음 요청에 최대 3개를 보낸다. 화면을 닫으면 사라진다. 질문·답변은 서버 이력/출력 검수 로그/공유 캐시에 저장하지 않는다. 기존 비용 원장에는 사용량만 남긴다.
- 사용자가 ‘아직 헷갈려요’로 선택한 용어만 설명 순서에 반영한다. 계좌·매수금액·수량·사전 메모는 자동 전송하지 않는다.

## 현재 한계와 완료 기준
- 기사 본문은 공급자의 실제 web_fetch 결과에서만 추린다. 검색 모델이 써 준 요약은 본문 근거로 쓰지 않는다. 본문을 못 받거나 발행일·대상 일치가 확인되지 않으면 원문 근거로 쓰지 않는다. 원인·뉴스 질문에 기사 본문이나 공개 발표가 하나도 없으면 답변 생성을 멈추고 이용 횟수를 차감하지 않는다. 모든 종목의 변동 원인을 확정하는 기능은 아니다.
- 시세는 실시간 보장이 없고 자유 날짜 조회/시간외 거래/화면에 표시된 임의 과거 차트 구간 자동 연동은 제공하지 않는다. 질문창에서 선택한 별도 기간을 명시한다.
- 출처 ID와 부호 검사는 전체 문장 진실성의 증명이 아니다. 일반 영향 설명도 실제 응답을 계속 검수해야 한다.
- 실계좌 손익·개인별 비중 진단은 이 작업 범위가 아니다.
- 회귀 테스트와 실제 API 답변은 별개로 확인한다. Chrome 조작 실패 때문에 실제 클릭·모바일·다크·로그인 흐름은 검수 완료로 표시하지 않는다.
- 재방문 개선 여부는 아직 측정하지 않았다. 호출 수나 테스트 수를 사용자 만족도 개선으로 보고하지 않는다.
