# 관리자 이용 현황

가입 규모와 실제 이용을 분리한다. `/admin`의 **이용 현황** 탭은 새 활성시간 측정, **성장** 탭은 기존 활동 로그를 사용한다.

## 활성시간과 방문

- 회원 DAU/WAU/MAU: 한국 시간 기준 오늘/최근 7일/최근 30일에 양수의 활성시간이 있는 고유 계정 수. 서버가 로그인 토큰으로 계정을 확인한다.
- 비로그인 활성 브라우저: 무작위 브라우저 ID 수. 사람 수가 아니며, 기기·브라우저 변경·저장소 삭제와 로그인 전후에 중복될 수 있다. 회원 기록에는 브라우저 ID를 저장하지 않는다.
- 활성시간: 탭이 보이고 창에 포커스가 있으며 마지막 조작 이후 60초 이내인 시간. 5초 간격으로 측정하며 중단된 타이머의 긴 공백은 합산하지 않는다. 조작 없이 오래 읽는 시간도 1분 이후 제외된다.
- 방문: 페이지를 새로 열거나 새로고침할 때 생성한다. 같은 페이지에서도 30분간 조작이 없었다면 다음 조작부터 새 방문이다. 여러 탭·로그인 전후는 별도 방문이다.
- 평균·중앙값: 선택한 기간에 양수의 활성시간이 있는 방문의 합산 시간으로 계산한다. 기간 경계에 걸친 방문은 해당 기간의 시간만 포함한다.
- 방문 빈도: 선택한 기간의 방문 수 / 활성 방문자 수. 이용한 날짜 역시 방문자별 고유 한국 날짜 수의 평균이다.
- 기능별 시간: 내 투자·차트·뉴스·기업 지표·주비 노트·배우기·기업/산업 설명·시장 해설 등. 종목 상세에서는 화면의 읽는 위치를 사용하며 약 5초의 분류 지연이 있을 수 있다.
- 관리자 계정과 자동화 브라우저는 새 측정에서 제외한다. 비로그인 자동화의 우회나 브라우저 계정 공유까지 사람을 식별하지는 않는다.

## 설명 탐색

같은 방문자·방문 안에서 기업/산업 설명 → 관련 기업 상세 이동 → 후속 질문 탐색 순서로 발생한 방문 수를 집계한다. 반복 클릭은 방문 수를 늘리지 않는다. 전환율 분모는 기업/산업 설명이 측정된 방문이며 표본이 없으면 `—`를 표시한다. 사용자가 내용을 이해했는지에 대한 직접적인 판정은 아니다.

## 기존 성장 지표 수정

- D1/D7은 기준일의 정확히 1일/7일 뒤 한국 날짜에 활동 로그가 있는지를 판단한다. 가입 당일만 사용한 계정을 재방문으로 세지 않는다.
- 대상 날짜가 오늘인 코호트는 제외하고 최근 완료된 7개 대상 날짜를 사용한다. 화면에서 7/14/30일을 바꿔도 이 코호트는 바뀌지 않는다. 표본과 돌아온 회원 수를 함께 표시한다.
- 기존 데이터의 가입 기준은 `user_portfolios.created_at`, 즉 포트폴리오 첫 저장일이다. 계정 생성일과 다를 수 있음을 화면에서 밝힌다.
- AI 분석 사용률은 선택 기간의 분석 사용 회원 수 / 전체 포트폴리오 저장 회원 수다. 호출 횟수를 분자로 쓰지 않으며 같은 회원의 반복 호출로 100%를 넘지 않는다. AI 촉은 분석 채택률에서 제외한다.
- 성장 탭의 DAU와 재방문은 기존 활동 로그 기준으로, 활성 사용시간 기준 DAU와 구분해 표시한다.

## 저장과 운영

`usage_samples`는 서비스 역할만 읽고 쓴다. 계정·방문·기록 ID, 시간, 기능/이벤트 열거값을 저장하며 종목·검색어·URL·보유정보·메모를 저장하지 않는다. 클라이언트가 전달한 계정 ID와 추가 필드는 버린다.

기록 UUID를 기본키로 사용하고 재시도 시 기존 기록을 변경하지 않는다. 한국 자정에서 시간 구간을 나누며 서버는 미래/오래된 시각·초과 시간·허용 목록 밖 필드 값을 거부한다. 전송은 약 30초 간격이며 탐색 이벤트·숨김·종료에서도 전송을 시도한다. 네트워크 차단이나 종료 도중 실패는 누락될 수 있다. 브라우저에 이용 기록의 영구 전송 대기열을 저장하지 않는다.

최근 30일을 조회하고 `cleanup-pii`의 정기 실행에서 30일이 지난 기록을 삭제한다. 정기 삭제 주기 때문에 물리적인 삭제는 다음 실행 때 이루어진다. 회원 탈퇴 API와 인증 계정의 외래키 cascade로 회원 기록을 삭제한다.

과거 활성시간을 기존 API 호출 기록에서 추정하지 않는다. 첫 보관 측정 이전의 날짜는 `미수집`, 표본 없는 평균/중앙값은 `—`로 표시한다. 저장소 오류는 오류로 표시하며 빈 차트로 바꾸지 않는다. 첫 보관 측정은 전체 수집 시작일이 아니라 현재 보관 데이터의 가장 오래된 시각이다.

모든 분석 조회는 1,000행 기본 제한을 넘어 페이지를 읽는다. 20만 행 이상에서는 불완전한 집계를 표시하지 않고 오류로 중단한다. 트래픽 확대 전에는 DB 집계로 전환해야 한다.

운영 적용 순서:

1. `supabase/migrations/2026-10-11_usage_samples.sql` 적용.
2. 앱 배포 후 일반 회원/비로그인 기록 저장 및 관리자 조회 확인.
3. 관리자 제외·중복 재전송·미수집 표시·탈퇴 삭제·정기 정리 결과 확인.

현재 운영 릴리스에 측정 이전 사용시간은 없으며 신규 코드 배포와 DB 적용 이후부터 기록이 쌓인다.
