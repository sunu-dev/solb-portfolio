# 모든 기업을 설명하기 위한 공급 체계

사용자 요청: 2026-10-11. 특정 누락 종목을 추가하는 방식에서, 지원 목록 전체를 지속적으로 설명하는 구조로 전환한다. 이 문서는 설계안이며 수집·생성·저장 서비스가 이미 구현됐다는 뜻은 아니다.

## 사용자가 얻어야 하는 결과

종목을 열면 ‘이 회사는 무엇을 하고, 누가 돈을 내고, 왜 이 종목을 살펴봐야 하는가’를 이해할 수 있어야 한다. 업종 이름과 제품 목록만으로 완료 처리하지 않는다.

모든 기업의 기본 설명은 다음 다섯 항목을 갖춘다.

| 항목 | 제공할 내용 | 완료 기준 |
|---|---|---|
| 실제 사업 | 무엇을 제공하고 어디에 쓰이는지 | 회사 자체의 제품·서비스 근거가 있는 한국어 설명 |
| 고객과 필요 | 누가 어떤 문제 때문에 쓰는지 | 확인된 고객 유형, 특정 고객명은 해당 근거가 있을 때만 |
| 수익 구조 | 무엇을 팔고 어떤 방식으로 돈을 받는지 | 실제 사업 구조의 근거, 매출 구성 수치에는 기간 표시 |
| 투자 점검 | 수요가 매출·비용으로 이어지는 과정과 확인할 조건 | 사업 사실과 주비의 해석을 구분 |
| 근거와 시점 | 위 설명을 뒷받침하는 자료 | 출처·자료 기준 기간·확인일·변경 이력 |

첫 화면은 사업 설명을 한두 문장으로 보여준다. ‘실제로 어디에 쓰이나요?’, ‘어떻게 돈을 버나요?’, ‘무엇을 확인해야 하나요?’로 이어지되 회사별 사실에서 답변을 구성한다. 상세 제품 비교·생활 예시·경쟁사 Q&A는 확장 단계로 관리한다.

## 분모와 현재 상태

- 현재 검색 목록16,302증권 중 기업 설명 대상은8,020종목이다. 이것은 중복 없는 발행회사8,020개라는 의미가 아니다. 여러 주식 종류·복수 상장을 하나의 회사로 연결하려면 발행사 식별자가 필요하다.
- 상세3·사업 요약64·제품목록만2,663·설명없음5,290. 짧은 요약이 있는67종목과 위 기본 다섯 항목을 갖춘3종목을 구분한다.
- `scripts/audit-company-explanations.mjs`가 모든8,020대상에 현재 수준, 부족한 기본 항목, 다음 단계, 우선순위, 기존 근거를 기록한다. 생성 결과는 `artifacts/company-coverage-20261011/inventory.json`이다.
- 기본 항목 미완료8,017종목. 작업 목록에 들어갔다는 사실을 콘텐츠 완료나 자동 수집 완료로 표현하지 않는다.
- `node scripts/audit-company-explanations.mjs --check-base`는 지원 대상 전체의 기본 다섯 항목이 채워지기 전까지 실패한다. 기존 `--check`의 노출 예시 요약 기준과 구분한다. 두 검사 모두 아직 prebuild에 통합하지 않았다.
- 원본 업종 미해결73종목, 개별 세부 사업 미검토7,967종목도 별도 지표다. 분류가 해결돼도 사업 설명은 미완료일 수 있다.
- 펀드·스팩·우선주·워런트·채권은 상품의 목적·조건을 설명하는 별도 경로가 필요하다. 일반 기업 설명을 복사해 전체 증권 설명 완료라고 집계하지 않는다.

## 데이터를 회사 단위로 관리한다

현재 TS 파일에 기업을 추가하는 구조는 편집 자료와 예외로 유지하고, 전체 콘텐츠는 버전이 있는 회사 레코드로 옮긴다.

| 레코드 | 핵심 필드 |
|---|---|
| 증권 | canonicalSymbol, market, securityType, issuerId, 유효 기간 |
| 회사 | issuerId, 공식 회사명, 국가, 공식 사이트, 사업 분야 여러 개 |
| 근거 | sourceId, URL, 문서 유형, 발행일/기준 기간, 수집일, 원문 해시, 해당 발행사 |
| 사업 사실 | factId, 제품·고객·수익 방식, supportingSourceIds, 자료 위치/발췌, 유효 기간 |
| 한국어 설명 | revisionId, issuerId, summary/customers/revenue/watch/questions, 각 항목의 factIds |
| 검수 | 검수 규칙 버전, 통과/보류 이유, 확인일, 검수 방식 |
| 운영 작업 | 다음 단계, 시도 수, 다음 시도 시각, 실패 사유, 마지막 성공 버전 |

회사 이름이 비슷하다는 이유로 합치지 않는다. 티커 변경·분할·합병·복수 주식 종류는 공식 발행사 식별자와 유효 기간을 확인한다. 샌디스크와 웨스턴디지털 같은 분할은 기존 설명을 공유하지 않는다. 현재 목록의 `verifiedIssuerSymbol`은 이미 제공처에서 확인한 연결만 보존하며, 다른 종목의 발행사 ID를 만들었다고 가정하지 않는다.

## 수집부터 화면까지의 공통 과정

1. **대상 동기화**: 검색 목록과 거래소 종목 마스터를 대조한다. 신규 상장·티커 변경·상장 상태 변경도 작업 목록에 반영한다. 삭제된 기업의 과거 근거는 이력으로 보존한다.
2. **발행사 확인**: 공식 발행사·종목 식별자를 연결한다. 충돌은 보류하며 이름으로 추정해 통과시키지 않는다.
3. **사업 근거 수집**: 미국은 회사 공식 사업 자료와 SEC 보고서, 한국은 공식 회사 자료와 사업보고서의 사업 내용 등을 후보로 사용한다. 거래소의 주요 제품 목록은 수집 출발점으로만 사용한다. 대량 프로필 자료가 필요하면 이용 조건·지원 범위·정확성을 먼저 검토한다.
4. **사실 정리**: 제품·쓰임·고객 유형·수익 방식·사업 부문을 추출하고 각각 근거 위치를 붙인다. 업종명에서 회사 사실을 생성하지 않는다. 신사업 개발과 상용 매출, 계약액과 인식된 매출을 구분한다.
5. **한국어 설명 작성**: 검증된 사실 묶음을 이용해 기본 다섯 항목과 후속 질문을 작성한다. 자동 문장 작성은 근거 수집의 대체물이 아니다. 원문 자료가 지시문처럼 보이더라도 수집·실행 규칙을 바꾸지 않는다.
6. **검수**: 발행사 일치·근거 누락·출처와 주장 일치·날짜·숫자·금융상품 구분을 자동 검사한다. 합병/분할, 미상용 기술, 복수 사업 충돌, 숫자 불일치는 사람 검수로 보류한다. 일반 항목도 산업·언어별 표본 검수로 실제 이해도와 오류율을 평가한다.
7. **저장·게시**: 통과한 설명만 새 버전으로 게시한다. 수집 실패나 검수 보류 시 이전의 검증된 설명을 유지하고 갱신 상태를 별도로 관리한다. 초보자가 읽는 화면에는 작업 단계·오류 로그를 노출하지 않는다.
8. **갱신**: 새 공시·사업 분할·제품 변화·상장 상태 변화는 해당 회사의 갱신 작업을 만든다. 분기/연간 문서 변화와 원문 해시를 이용해 변화가 없는 자료를 다시 작성하지 않는다. 구체적인 점검 주기는 실제 수집 성공률과 변경 빈도를 측정해 정한다.

회사를 여는 즉시 외부 자료를 여러 번 수집하고 문장을 생성하면 응답이 늦고 실패가 그대로 보인다. 사전 배치와 저장한 설명을 기본으로 제공하며, 사용자 조회에서 누락이 발견되면 기존 작업 목록의 우선순위를 올리는 방식이 적합하다. 구현 시 현재 저장 인프라 활용 여부를 확인하되 이 설계 단계에서 새 서비스나 DB를 만들지 않는다.

## 우선순위와 전체 범위

- 먼저 화면에 이미 등장하는 예시를 처리한다. 현재836개 예시 중396개는 설명이 없고402개는 제품 목록만 있다. 검토한 사업 설명이 없는 예시는798개다.
- 이후에는 분류·발행사 충돌을 정리하면서 전체 미완료 기업을 처리한다. 인기 종목만 선정해 나머지를 작업 목록에서 제외하지 않는다.
- 사용자 조회로 우선순위를 높일 수 있지만 기본 분모는 지원 목록 전체다. 우선순위는 처리 순서이며 제품 지원 범위를 뜻하지 않는다.
- 초기 배치에서 자료 접근 성공률, 회사당 처리 시간, 검수 보류율, 산업별 오류율과 실제 비용을 측정한다. 처리량을 확인하기 전에 전체 완료 날짜나 비용을 확정하지 않는다.

## 일러스트는 사업 분야 단위로 준비한다

기업마다8,020장의 그림을 만드는 방식 대신 확인한 실제 사업 분야의 그림을 공유한다. 회사의 복수 사업은 해당 분야로 전환해 보여준다. 그림은 사업 설명을 보조하며 회사 정보가 없는 것을 메우는 수단으로 쓰지 않는다.

- 현재42개 산업·사업 분야에 각각 전용 SVG 장면을 연결한다. 원본303업종에303개 고유 장면을 만들었다는 의미는 아니다.
- 신규 분야 정의에 대표 기업·근거·설명·그림·대체 텍스트·캡션을 함께 준비한다. 기존 분야와 사실상 같은 사업은 장면을 공유할 수 있지만 다른 사업의 그림을 자동으로 붙이지 않는다.
- 원자로 개발은 설계·실증·허가, 핵연료는 원료·가공·연료봉, 발전은 발전소 운영·전기·고객으로 구분한다. 양자컴퓨팅과 양자내성 보안도 같은 그림으로 처리하지 않는다.

## 완료를 판단하는 기준

1. 지원 목록의 모든 기업 대상 종목이 작업 목록에 존재한다. 현재8,020/8,020으로 확인했다.
2. 모든 대상에 실제 사업·고객·수익·투자 점검·근거가 있는 기본 설명을 제공한다. 현재3/8,020으로 미완료다.
3. 모든 노출 기업에서 기본 설명으로 연결되며 ‘설명 없음’ 또는 제품 목록만 있는 화면이 남지 않는다.
4. 분류 커버리지, 기본 설명 커버리지, 상세 Q&A 커버리지, 자료 갱신 상태, 그림 커버리지를 각각 보고한다.
5. 신규 상장·사업 변경·수집 실패를 넣어도 누락을 탐지하고 재시도하며 검증된 버전을 유지한다.

현재 구현: 전수 감사와 기본 설명 작업 목록 생성, 기존 설명과 분류 연결,42분야 그림. 미구현: 전체 회사 식별자 매핑, 대량 근거 수집, 사실/설명 버전 저장, 자동 검수·게시·재시도·갱신. 다음 구현은 이 공급 과정에 맞춘 소규모 실측 배치부터 시작한다.
