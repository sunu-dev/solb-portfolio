# AI 기능 데이터 흐름 맵

목적: 비용 통제, 개인정보 최소화, 출력 감사, 금융위 법령해석 자료 준비를 위한 현재 구현 기준 지도.

## 1. 종목 AI 분석

- 엔드포인트: `POST /api/ai-analysis`
- 인증: 로그인 사용자 전용, 서버에서 Bearer token 검증
- 사용자 입력:
  - 종목, 현재가, 등락률
  - 보유수량, 평균 매수가, 현재 손익
  - 목표 수익률, 손절가, 포트폴리오 비중
  - 투자자 유형, 종목 결정 메모
- 시장 입력:
  - RSI, 추세, 이동평균 교차, 패턴, 볼린저 밴드, MACD, 거래량
  - PER, EPS, 52주 고저, 섹터
  - 최근 뉴스, 시계열 컨텍스트
- 출력 방향성:
  - 긍정/관망/주의 결론과 신호
  - 상승·하락 시나리오
  - 레버리지·인버스는 서버 후처리로 방향성 제거
- 저장:
  - `ai_usage`: 사용자·종목·멘토·날짜
  - `ai_cost_ledger`: 모델·토큰·추정 비용·지연시간
  - 프롬프트와 응답 원문은 비용 원장에 저장하지 않음
- 남은 위험:
  - 개인 보유정보와 목표를 직접 반영하므로 법령해석 자료의 핵심 검토 대상
  - 응답 캐시가 없어 동일 조건 반복 호출 시 비용이 다시 발생

## 2. AI 촉

- 엔드포인트: `POST /api/ai-chok`
- 인증: 서버에서 사용자 확인
- 개인화 입력:
  - 보유 종목 제외 목록
  - 투자자 유형
  - 핵심 보유 종목의 비중·신호·메모 맥락
  - 포트폴리오 섹터 집중도
- 시장 입력:
  - 종목별 현재가, 당일 변동률, PER, 52주 위치
  - VIX 구간, 시장 이벤트, 당일 상승·하락 상위
- 캐시 키:
  - 사용자 + 투자자 유형 + KST 날짜 + day/night 세션 + VIX 구간
- 비용 없는 경로:
  - `intent=fetch`
  - 정확 캐시 또는 최근 24시간 캐시
  - 객관 수치 기반 결정론적 폴백
- 출력 방향성:
  - 서로 다른 섹터의 관찰 후보 3개와 이유
- 저장:
  - `ai_chok_cache`, `ai_chok_recommendations`, `ai_usage`, `ai_cost_ledger`
- 남은 위험:
  - 사용자의 포트폴리오 약점을 보완하도록 후보를 고르는 구조는 개인화 추천으로 해석될 가능성이 큼

## 3. 알림과 digest

- `check-alerts`, `morning-brief`, `monthly-d3-reminder`는 현재 LLM을 호출하지 않는다.
- 사용자 포트폴리오와 설정값을 서버 규칙·템플릿으로 조합한다.
- 비용 원장 대상은 아니지만 목표·손절 등 방향성 문구에 대한 컴플라이언스 감사 대상이다.

## 4. 보조 AI 기능

### 포트폴리오 OCR

- 사용자가 업로드한 이미지가 Gemini로 전달된다.
- 이미지 자체는 주비 DB에 저장하지 않으며, 성공 시 사용자 ID 또는 비로그인 IP와 인식 종목 수를 `ai_usage`에 기록한다.
- 모델·토큰·지연시간·추정 원가는 공통 비용 원장에 `portfolio-ocr`로 기록한다.
- 전체 AI 일일 하드캡과 OCR 전용 일일 하드캡을 모두 적용하며, 공급자 데이터 처리 조건은 별도 확인해야 한다.

### 신규 상장 한글명 보강

- 종목 코드·영문명·거래소만 전달한다.
- 투자 개인화가 없고 관리자 보조 기능이다.
- 공통 프로바이더를 사용하며 비용 원장에 `admin-listing-name`으로 기록한다.
