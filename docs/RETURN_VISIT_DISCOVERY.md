# 주비 노트·배우기의 지속 방문 설계

2026-10-15 사용자 명시 승인. 핵심 비즈니스 작업이며, 구현·검증 중이다.

## 목적
매일 방문했을 때 지난번 이후 달라진 것을 이해하고, 오늘 생긴 질문을 풀고, 다음에 확인할 일이 남도록 한다. 콘텐츠 분량과 다양성도 늘리되 사실이 변하지 않았는데 새 소식인 것처럼 보이게 하지 않는다. 사용자 발화의 ‘메일 와서’는 매일 방문 맥락으로 해석했으며 이메일 발송 기능이나 발송을 승인받은 것은 아니다.

## 발견한 현 상태
- StockAnalysisQuestions의 질문은 6개로 고정되고 같은 3개가 먼저 노출된다.
- StockLearning은 고정 설명 3개와 퀴즈로 구성된다. 읽은 기록은 컴포넌트를 닫으면 사라진다.
- 질문형 AI 요청(handleMentorSelect)은 최근 뉴스를 전달하지 않는다. 일반 분석 요청과 차이가 있다.
- 회사·산업 해설은 풍부해졌지만 새 소식·이전에 읽은 설명·이어 읽기가 연결되지 않는다.

## 이번 구현 범위
1. 주비 노트에 실제 공개 시세·뉴스로 구성하는 변화 요약을 제공한다. 최초 방문/재방문/같은 자료/누락·지연을 구분하고 기준 시각·출처를 표시한다.
2. 이 브라우저에서 읽은 시점과 비교한다. 계정별 기록을 분리하고 로그아웃·계정 전환 때 정리한다. 다른 기기까지 동기화했다고 표현하지 않는다. 화면을 열기만 하고 실제 읽지 않은 내용을 읽음으로 기록하지 않는다.
3. 질문 목록을 상황별 공개정보 질문으로 확장한다. 뉴스·지표·사업 분야에 맞는 질문이 먼저 나오고, 질문 선정 이유를 짧게 보여준다. 제목만 바꾸거나 무작위로 반복하지 않는다.
4. 질문형 AI에도 날짜·출처가 있는 최근 뉴스 제목을 전달한다. 서버가 허용된 질문 ID를 검증하고 구체적인 질문에 답하도록 한다. 개인 보유·목표·메모·읽은 기록은 모델로 보내지 않는다. 제목을 기사 본문이나 원인 확정 근거로 사용하지 않는다.
5. 질문별 캐시를 분리하고 새로운 기사 등 근거가 바뀌면 이전 답변과 구별한다. 유효한 답변만 기존 일일 횟수를 사용하며 실패는 무차감·재시도다.
6. 배우기를 재무·사업·산업·거시경제 등 다양한 설명으로 확장한다. 쉬운 뜻 → 명시된 가상 예시 → 실제 자료에서 확인할 것 → 출처 → 이어지는 질문 순서다. 퀴즈를 필수 또는 진도 기준으로 삼지 않는다.
7. 읽던 설명과 아직 읽지 않은 관련 설명을 연결한다. 새 뉴스가 없는 경우 자료 상태를 정직하게 알리고 심화 설명으로 연결한다.
8. 새 자료 열람·설명 읽기·후속 탐색을 집계하고 기존 재방문(D1/D7)과 함께 관리자에서 확인한다. 종목·보유내역·뉴스 제목·학습 내용 자체를 이용 통계로 전송하지 않는다. 실제 효과는 운영 관찰 뒤 판단한다.

## 공급과 운영의 경계
- 기존 종목 시세·뉴스·기업 지표 API를 활용한다. 노트·배우기 열람 자체로 AI 자동 생성이나 별도 유료 호출을 만들지 않는다.
- 정기 시장 관찰 작업은 별도 구현돼 있으나 Hobby 요금제의 10분 cron 제약으로 미배포 상태다. 이 기능을 이미 자동 수집 중인 것으로 설명하지 않는다.
- 개별 기업의 계약·고객·미래 실적은 업종명에서 추정하지 않는다. 근거가 없는 질문에는 필요한 자료와 미확인 상태를 설명한다.

## 검증 계획
- 순수 로직: 실제 새 자료/중복·오래된·미래 뉴스/동일 시각 시세/자료 누락/최초·재방문/다른 계정/저장 차단/동시 업데이트.
- AI 경계: 허용 질문 ID·공개정보만 전달·질문별 캐시·뉴스 변경·실패 무차감·이전 답변 표시.
- 브라우저: PC/모바일·라이트/다크·기본/넓게, 첫 방문→읽기→다음 방문, 새 뉴스/같은 자료/자료 실패, 계정 전환, 이어 읽기와 출처·관련 기업 탐색.
- 빌드·필수 검사·통계 집계 테스트, 운영 실제 자료 확인. 격리된 데이터 주입과 실계정 검수는 구분한다.

## 구현한 탐색 흐름
- 주비 노트: 현재 제공된 최근 7일 기사 제목·출처·발행 시각과 실제 시세 기준 시각을 표시한다. 사용자가 `여기까지 확인했어요`를 누른 뒤의 방문부터 비교한다. 자동 열람 판정이 아니라 명시적 확인 기록이다.
- 뉴스 조회 실패는 새 소식 없음과 분리하며 비교 기준을 갱신하지 않는다. 가격은 통화가 같고 제공 시각이 더 새로울 때만 비교한다. 가격 차이는 투자 수익률이나 변동 원인으로 표현하지 않는다.
- 기사 → 배경 개념 → 본문의 연결 용어 → 관련 질문 3개 → 실제 기업·산업 설명으로 이어진다. 본문 링크는 문단당 최대 2개이며 현재 읽는 개념 자체로 연결하지 않는다. 탐색 경로는 최대 30단계로 제한하고 이전 설명·스크롤 위치로 돌아갈 수 있다.
- 학습 해설은 20개, 편집한 후속 연결은 60개다. 모든 해설이 연결 그래프에 포함되며 각 해설의 후속 질문이 존재하는지 검사한다. 기존 42개 산업·303개 업종 탐색으로 같은 패널에서 이어간다. 20개 해설은 일반 개념이며 모든 기업의 개별 재무·계약 분석을 뜻하지 않는다.
- 질문 20개는 최근 뉴스 제목의 주제와 열어본 기록으로 정렬한다. 구체적인 산업·재무 자료가 없는 경우 해당 기업의 실제 문제로 단정하지 않는다. 첫 3개 외에는 접어 두고, 각 질문에서 AI 횟수 없이 배경 해설로 이동할 수 있다.
- 질문형 AI는 서버가 허용한 질문 ID와 멘토 조합만 받는다. 공개 뉴스 제목·출처·날짜를 전달하고, 응답 캐시는 계정·종목·질문·시세·기사·PER/EPS로 구분한다. 최대 100개를 보관하며 로그아웃 시 기존 분석 캐시 정리 경로를 따른다. 실패 무차감과 개인 보유·메모 비전송을 유지한다.
- 학습의 `읽었어요`는 사용자의 명시적 표시다. 이해도를 입증하는 시험 점수로 해석하지 않는다. 마지막 주제·읽은 주제·최대 40개 종목의 비교 자료를 계정별 브라우저 저장소에 보관한다. 기사 제목·URL 대신 제한된 지문만 기록한다. 기기 동기화·메일 발송은 구현하지 않았다.
- 관리자 이용 현황에 `변화 확인 / 기사 원문 열기 / 설명 열기 / 읽었어요 선택 / 이어서 읽기`의 방문 수를 추가했다. 같은 방문의 같은 이벤트는 한 번으로 합친다. 순차 전환율이나 인과적 재방문 효과로 해석하지 않는다. 종목·기사·학습 본문은 통계에 전송하지 않는다.

## 운영 순서
- `supabase/migrations/20261015000200_discovery_usage.sql`만 적용해 기존 이벤트 CHECK를 확장한다. 잠금 3초·문장 30초 제한과 트랜잭션을 사용한다. 기존 클라이언트 이벤트는 계속 허용한다.
- 시장 관찰 마이그레이션·cron은 이 배포에 포함하지 않는다.
- 격리 release worktree의 명시된 파일만 커밋한다. 증거와 파일 목록은 `artifacts/return-visit-20261015/`에서 관리한다.
- 추가 이벤트는 배포 이후부터 쌓인다. 재방문 효과는 관리자 성장 탭의 D1/D7 및 실제 이용 기록과 함께 관찰해야 하며, 구현만으로 체류·재방문 개선을 입증하지 않는다.

## 운영 검수 후 보완
- 실사용 공개 API를 쓰는 비로그인 운영 검수에서 새로고침 시 기존 포트폴리오 초기화가 읽기 기록까지 지우는 충돌을 발견했다. 익명 상태의 일반 시작에서만 `joobi_discovery_v1:guest` 하나를 보존한다. 로그인·로그아웃·계정 전환이나 이전 계정 소유자가 남은 시작에서는 계정 기록과 함께 제거한다. 포트폴리오·다른 계정 기록을 보존하는 예외로 확대하지 않는다.
- 보완 후 전체 1,446개 테스트 통과·1개 skip, TypeScript·운영 빌드 성공. 새로고침 시 익명 기록 유지와 계정 변경 시 분리/삭제를 포함한 후속 브라우저 8개 검사 통과·pageerror 0. 기존 120개 화면 검수는 표시 코드가 변경되지 않아 유지한다.
