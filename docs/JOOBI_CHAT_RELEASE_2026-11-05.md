# 주비 질문 연결·검색·진행 상태 구현

설계 근거: [신뢰·속도 설계](JOOBI_CHAT_RELIABILITY_DESIGN_2026-11-05.md). 배포 결과·ID는 artifacts/joobi-chat-quality-20261105/RELEASE.md에 기록한다.

## 구현한 동작
- 서버에서 질문의 회사명·정확한 티커를 공식 종목 목록 스냅샷/기존 별칭에 연결한다. AI가 임의 티커를 만들지 않는다. 질문에 명시한 대상이 기존 선택보다 우선한다.
- 마이크론/MU, 하나마이크론, MUU를 구분한다. 여러 대상은 후보를 보내며 사용자가 명시적으로 확인한 후보만 사용한다. 비교 질문을 여러 종목 조회처럼 가장하지 않는다.
- 확정한 대상·시장·기간을 답변에 붙이고 다음 질문에도 전달한다. 명시적 시장 전환은 이전 회사보다 우선한다. 이전 답의 문장은 사실 근거로 사용하지 않는다.
- 회사 설명과 시세/기존 공개 자료를 병렬 조회한다. 이전 대화에 하락 이야기가 있어도 단순 용어 질문은 뉴스 조회를 생략한다.
- 본문이 없거나 회사 기사만 있고 업종/시장 배경이 부족하면 한 번 더 검색한다. 최대 두 차례 검색·네 번 본문 조회. 원문 수집과 게시일/대상 검수는 유지한다. 범위 검사이지 자동 인과 증명은 아니다.
- 서버 인스턴스 간 공개 기사 결과를5분 구간으로 재사용한다. 종목·기간·기준 거래일/시각·기사 검색 단서·현재 시간 구간으로 키를 나눈다. 사용자 질문/답변/계좌 정보는 공유하지 않는다. 빈 결과는 영구 캐시에 남기지 않는다.
- 비용 기록은 캐시 바깥에서 실제 새 호출에만 수행하며 쓰기 대기는3초로 제한한다.
- 실제 서버 단계 이벤트와 검수 완료 결과를 NDJSON으로 전송한다. 화면은 자료 조회→기사→필요할 때 보완→설명 정리→검수 상태를 받는다. 검수 전 모델 문장은 출력하지 않는다.
- 스트림 안의 실제 HTTP결과(401/422/503 등)를 클라이언트가 처리한다. 전송 계층의200을 답변 성공으로 오인하지 않는다. 기존 JSON API는 유지한다.
- 질문/답 원문 없는 단계별 서버 소요시간 로그. 상태 이름·시각·최종 결과 코드만 기록한다.
- 기사 출판사명은 알려진 도메인의 고정 이름으로 전달한다. 업종도 하락한 자료에서 ‘이 회사만 하락’하는 오류를 검사한다. 모든 의미 오류를 자동으로 잡는 것은 아니다.
- 추천 질문은 짧은 버튼으로, 등록 종목은 입력 상자 안에, 입력은 작성 길이에 따라 늘어난다. 데스크톱 첫 대화창 높이를 줄이고 실제 작은 창에서는 입력/전송 영역을 유지한다.

## 지속 검수 방법
기존 prebuild 전체 테스트에 종목/후속 맥락/시장 전환/확정 후보/검색 보완 조건/스트림 오류 및 한글 분할 전송 회귀검사를 포함한다.

공개 질문의 실제 API 검사(비용 발생, 기본 비활성):
- `JOOBI_LATENCY_LIVE=1 JOOBI_LATENCY_RESOLVED_ONLY=1 npx vitest run src/__tests__/assistantLatencyLive.test.ts`
- `JOOBI_EFFORT_LIVE=1 npx vitest run src/__tests__/assistantEffortLive.test.ts`
- 본문 수집 실패는 `JOOBI_SOURCE_DIAGNOSTIC=1`의 전용 테스트로 공개 도구 메타데이터만 확인한다. 일반 운영에서 이 플래그를 켜지 않는다.

실제 답은 질문에 직접 답하는지/같은 대상·날짜인지/근거와 조건부 해석을 구분했는지/초보자가 이해할 수 있는지 읽는다. 검사 통과 개수는 답변 신뢰도 점수가 아니다.

## 이번 실측과 한계
- 보완된 공개 파이프라인 첫 질문: 조회약1.7초+기사8.3초+생성16.7초. 후속 생성15.2초. 각1회.
- 로컬 인증 API: 후보 확인422, 마이크론MU/미국 연결200; 실제 진행 단계6개. 첫 바이트7ms, 전체32.8초(시작·인증·기록 포함, 개발서버).
- 수집이0건인 실패도 발생했다. 실제 경로는 본문/공개 발표가 없으면 정상 원인 답변을 생성하지 않고 횟수를 차감하지 않는다. 검사 스크립트도 같은 선행 조건을 요구하도록 강화했다.
- Haiku medium 유지. low의 의미 오류 때문에 속도만 보고 전환하지 않았다.
- Chrome 데스크톱1280×800/작은 창390×360, 예시→입력/전송 배치 확인. 실제 아이폰 키보드, 로그인 연속 대화의 브라우저 시각 검수는 별도다. 인증 요청 경로는 API로 검사했다.
- 오타 후보 추천·미등록/변경 종목의 온라인 보완, 다중 회사 비교, 핵심 문장별 근거 계약, 사용자 피드백 UI, 운영 P50/P95 집계는 후속 작업이다. 이번 적용을 설계 전체 완료나 전 종목 설명 검수 완료로 부르지 않는다.
