# 공통 시장 관찰·후속 브리핑

사용자 확정 방향(2026-10-15): 사용자가 특정 산업의 하락을 알려줄 때마다 전용 화면을 추가하는 방식 대신, 주비가 정기적으로 시장을 관찰하고 중요한 변화와 이후 달라진 점을 설명한다. 보유 종목이 없는 사용자도 이용하며, 내 투자와의 연결은 추가 정보다.

## 구현 범위

- 홈과 오늘의 브리핑: 중요한 소식 1건 → 같은 화면의 주비 리포트.
- 리포트: 주요 소식·한국·미국·산업별·이후 달라진 점. 뜻풀이 → 일반적인 영향 경로 → 다음 확인 항목 → 보유 종목 연결 → 출처·이력. 첫 목록은 5건, 나머지는 펼친다.
- 실제 관찰한 변화, 거래소 공식 공시, 확인된 경제 발표 수치, 기사 제목에서 찾은 관련 소식을 구분한다.
- 보유/관심 정보를 수집 작업에 전달하지 않는다. 샘플 종목은 개인 연결에서 제외한다. 보유 연결은 사업 근거를 확인한 산업의 기업 목록에 한하며, 직접 피해·수혜로 단정하지 않는다.
- 조회 시 AI 생성이나 외부 자료 수집을 실행하지 않는다. 정기 작업이 공통 결과를 저장하고 모든 방문자가 같은 기록을 조회한다. 새 LLM 호출은 없다.

## 관찰 범위와 주기

| 원천 | 범위 | 주기 |
|---|---|---|
| Yahoo Finance | 코스피·코스닥·S&P 500·나스닥 종합 | 10분 |
| Yahoo Finance | 미국 주요 업종 ETF 11개 및 반도체 SOXX | 10분 |
| Yahoo Finance | 원·달러 환율, WTI·금 선물, 미국 10년 국채금리 | 10분 |
| 한국거래소 KIND 공식 RSS | 유가증권·코스닥 시장조치 중 CB 발동/해제·사이드카 공시 | 10분 |
| 기존 경제 자료 수집기 | 기존에 확인할 수 있는 발표 수치·일정 | 10분 작업에서 기존 캐시 재사용 |
| Google News RSS | 한국 시장·미국 시장 및 정책 관련 검색 | 10분 |
| Google News RSS | 공통 `SECTORS` 목록 전체(현재 42개 산업·세부 분야) | 2시간 |

시세 대상은 총 20개다. 미국 ETF를 국내 업종이나 세계 산업 전체의 수익률로 표시하지 않는다. 42개 검색 성공은 42개 산업의 기사 본문과 모든 기업을 검증했다는 뜻이 아니다. 경제 자료 원천에 경고가 있으면 전체 확인을 성공으로 세지 않는다.

주요 업종 ETF의 같은 거래일 자료가 8개 이상일 때 업종 간 등락 차이를 비교한다. 등락 차이를 자금 유입·유출의 증거로 표현하지 않는다. 최근 변동 자료가 충분하면 평소 변동 범위도 참고하고, 부족하면 공개한 고정 등락 기준으로 관찰한다. 국채금리 변화는 %포인트 단위를 사용한다.

## 서킷브레이커 사실 확인

- 지수 -8%만으로 발동을 만들지 않는다. 기사 제목의 발동 가능성·제도 설명도 공식 발동으로 승격하지 않는다.
- KIND RSS의 정확한 시장 작성자·`시장조치` 분류·해당 날짜의 접수번호·KIND 원문 주소를 함께 확인한다. 파생상품시장 후속 공시는 현물시장 발동으로 중복 집계하지 않는다.
- 항목이 있는 RSS의 채널 작성 시각이30분 넘게 오래됐거나 응답 형식이 다르면 실패다. KIND가 자정 이후 공시 없는 날 반환하는 빈 RSS는 공식 제목·유효한 RSS·fresh HTTP Date(±60초)·Age 없음/0을 함께 확인할 때만 정상 조회로 처리한다. 빈 목록만으로 시장조치 부재나 해제를 추정하지 않는다. 원천 지연 가능성도 구분한다.
- 같은 날짜·시장·조치의 발동/해제는 한 기록으로 묶는다. 첫 수집 때 이미 해제됐어도 RSS에 남은 발동부터 이력에 넣는다.
- 표시 시각은 **공시 시각**이다. 실제 발동/재개 시각이라고 표시하지 않는다. 20분이 지났다는 이유로 해제를 추정하지 않는다.
- 첫 단계 조건은 공식 제도 설명을 바탕으로 풀어쓰며, 실제 적용 단계와 상태는 공시 원문을 우선한다.
- 사이드카 공시를 시장 전체 거래 중단으로 표시하지 않는다.

## 저장·안전한 실패

`market_watch_events`: 공통 기록과 최근 변경 이력(최대 20개). `market_watch_runs`: 마지막 발행 시각·원천별 확인 건수·경고·수집 잠금.

- `claim_market_watch`: 범위별 수집 잠금. 서로 다른 서버 인스턴스의 중복 실행을 막고 4분 뒤 만료된다.
- `publish_market_watch`: 소유한 잠금이 유효할 때만 사건과 확인 범위를 한 트랜잭션으로 저장한다. 실패 시 마지막 발행 결과를 보존한다.
- 익명·회원은 테이블과 쓰기 함수를 직접 호출할 수 없다. 서버의 service-role 클라이언트와 인증된 cron만 수집·발행한다.
- 공개 `/api/market-watch`는 저장 결과만 읽는다. 사용자 요청으로 수집비나 생성비가 발생하지 않는다.
- 의미 있는 변화가 없으면 새 변경 이력을 추가하지 않는다. 오래된 관측으로 더 새로운 관측을 덮지 않는다. 크게 움직였던 지표가 관찰 기준 아래로 내려오면 최근 2일 동안 후속 기록으로 남긴다.
- 시장 관찰이 30분, 산업 검색이 150분 넘게 갱신되지 않으면 지연을 표시한다. 일부 실패와 전체 미수집을 평온한 시장으로 해석하지 않는다.
- 보관은 최근 관찰 30일, 화면의 사건 기준 시각은 최근 7일이다. 영구적인 원본 뉴스/공시 아카이브가 아니다.

## 운영 예약과 적용 순서

2026-10-22 복구 과정에서 연결된 DB의 두 테이블 누락(PGRST205)을 확인해 시장 소식 전용 SQL을 적용했다. 기존 사용자 테이블은 변경하지 않았다. Vercel 계정은 Hobby이며, 하루보다 잦은 Vercel cron을 지원하지 않으므로 시장 관찰의 두 예약은 기존 Supabase의 pg_cron·pg_net을 사용한다. 다른 일일 Vercel 예약과 요금제는 유지한다.

1. `supabase/migrations/20261015000100_market_watch.sql`을 DB에 적용한다.
2. `20261022000100_market_watch_scheduler.sql`로 pg_cron·pg_net과 관리자 전용 `enqueue_market_watch`를 설치한다. 함수는 지정된 두 범위와 `https://joobi.kr`의 두 수집 경로만 호출한다.
3. 연결한 프로젝트의 운영 환경변수를 불러온 뒤 `node --env-file=<운영 env 파일> scripts/configure-market-watch-secret.mjs`로 기존 CRON_SECRET을 Vault에 설정한다. 키 값을 출력하지 않으며 임시 SQL은0600 권한으로 만들고 즉시 제거한다. cron 명령에는 비밀값을 넣지 않는다.
4. 인증된 수집 경로와 공개 조회 경로·화면을 배포한다. Vercel의 두 잦은 예약은 vercel.json에 추가하지 않는다.
5. 운영 도메인 전환 후 `supabase/operations/market-watch-schedule.sql`로 `joobi-market-watch`(10분)·`joobi-industry-watch`(2시간) 두 작업을 활성화한다.
6. cron.job_run_details의 실행 성공뿐 아니라 net._http_response의 HTTP 결과와 market_watch_runs.last_run의 실제 발행 시각을 함께 확인한다. pg_net 큐 등록 성공은 자료 수집 성공과 다르다.

공개 API는 여전히 저장 결과만 읽는다. 조회 시 수집·생성·쓰기를 시작하는 우회 경로는 추가하지 않았다. 자료가 빠지면 원천별 확인 수와 경고를 보존한다. 운영 배포·예약 실검수 결과는 `artifacts/design-release-20261022/REPORT.md`에 기록한다.

검수 근거는 `artifacts/market-watch-20261015/`에 있다. `local-feed.json`은 실제 공개 원천을 수집해 로컬 DB에 발행한 결과이며, `browser-results.json`의 failure/stale/empty는 표시를 확인하기 위해 주입한 조건이다. 운영 데이터 검수와 구분한다.
