# 주비 공통 UI 기준

주비의 UI는 주식 초보자가 화면을 바꿔도 같은 동작을 알아볼 수 있게 설계한다. 같은 역할에는 같은 글꼴·크기·상태 표현을 사용하고, 정보의 중요도는 여백과 위계로 구분한다. 설명의 내용과 순서는 [제품 및 설명 원칙](JOOBI_EXPLANATION_PRINCIPLES.md)을 따른다.

## 구현의 기준점

- `src/app/globals.css`: 글꼴 `--font-ui`, 테마별 의미 색, 글자·컨트롤 크기 토큰.
- `src/components/ui/AppUI.module.css`: 기본 동작·필드·탭·스위치·페이지/그룹 제목의 역할.
- `src/components/ui/ReadingUI.module.css`: [읽기 화면 기준](READING_UI_SYSTEM.md), 섹션 제목·본문·펼치기. 보조 동작은 AppUI를 조합한다.
- `src/components/ui/{button,input,tabs,card}.tsx`: 기존 컴포넌트 API를 유지하면서 같은 역할을 사용한다. 네이티브 JSX도 AppUI를 직접 사용한다.
- `src/config/designTokens.ts`: 기존 코드 호환용 별칭. 새 색상/글자 기준을 별도로 정의하지 않는다.

## 역할별 기준

| 역할 | 기준 | 사용 |
| --- | --- | --- |
| 페이지 제목 | 24px / 650 | `pageTitle` |
| 읽기 섹션 제목 | 20px / 650 | ReadingUI `sectionTitle` |
| 설정·카드 그룹 제목 | 16px / 650 | `groupTitle` |
| 본문 | 15px | `--type-body-size` |
| 버튼·탭·펼치기 | 14px / 550 / 줄높이 1.6 | AppUI 동작 또는 ReadingUI `disclosure` |
| 날짜·출처·보조 설명 | 12px | `--type-caption-size` |
| 입력값 | 16px | `field`; 모바일 입력 확대 방지 |

일반 동작·탭·필드는 최소 높이48px, 아이콘 동작은44×44px를 확보한다. 모서리는8px, 키보드 초점은 공통 외곽선으로 표현한다. 모바일에서도 역할별 글자 크기를 줄이지 않는다. 긴 라벨과 설명은 줄바꿈한다.

`primaryButton`은 주요 완료/저장, `secondaryButton`은 보조 선택/가져오기, `textButton`은 낮은 강조의 이동, `dangerButton`은 삭제, `iconButton`은 닫기/계정 메뉴에 사용한다. 선택 버튼은 `aria-pressed`, 탭은 기존 접근성 API를 유지한다. 스위치는48px 입력 영역 안에40×24px 트랙을 두며 상태와 라벨을 함께 제공한다.

색은 중립 표면과 텍스트를 기본으로 한다. 상승·하락·위험·성공은 해당 의미 색을 유지한다. 카카오 로그인 노랑, 로고, 종목/차트/지도 시각화, 코드 고정폭은 의도된 예외다. 모든 화면을 같은 카드나 같은 정보 밀도로 만들지는 않는다.

브랜드 강조에는 `--surface-warm`(크림색 표면), `--surface-feature`·`--text-on-feature`(리포트), `--brand-highlight`·`--text-on-highlight`(옐로 동작)를 사용한다. 주요 등록 동작은 공통 `accentButton`을 조합한다. 일반 `primaryButton`의 중립색과 손익 의미 색은 유지한다. 기업 로고는 `CompanyMark`의 로컬 원본을 사용한다. 승인된 홈 그림은 `public/illustrations/home/*-handdrawn-v2.png`의 단순한 평면 펜 드로잉을 사용한다. hover·눌림 반응은 짧게 제공하며 `prefers-reduced-motion`에서는 이동과 전환을 생략한다.

핵심 사용 화면의 최신 적용(2026-10-22): 헤더·모바일 메뉴는 Navigation 모듈, 본문·사이드바는 AppFrame 모듈로 폭·여백을 관리한다. 헤더 높이는 `--app-header-height`로 공유하며, 화면 폭1024px 미만에서는 하단 메뉴를 사용한다. 선택 메뉴는 옐로 선 또는 크림색 아이콘 배경으로 표시한다. 통화·종목/분석 같은 작은 선택 그룹은 AppUI `segments`·`segment`를 사용한다. 자산 요약은 평가금액을 먼저 읽고 평가손익·원금·종목 수로 이어지며 계산/시세 기준은 유지한다. 시장 소식은 홈의 자산·종목 목록 또는 첫 등록 영역 뒤에 둔다. 종목 상세는 공통 테마 색과 기업 로고를 사용하고, 설정은 같은 제목·구분선·컨트롤 기준을 따른다. 보조 정보에 색·이모지·큰 상자를 동시에 반복하지 않는다.

펜 드로잉은 다크 모드에서도 선을 식별할 수 있도록 `--illustration-surface-warm`·`--illustration-surface-neutral`의 밝은 종이색 영역에 배치한다. 고정 높이 그림 영역은 relative 부모와 Image `fill`·`object-fit:contain`으로 전체 그림을 담는다. 페이지의 가로 넘침은 `overflow-x:clip`으로 막아 헤더의 sticky 동작을 보존한다.

## 적용 범위와 확장

종목 상세에 이어 설정, 로그인/초대/연령 확인, 계정 메뉴, 온보딩, 종목 편집, CSV/OCR 가져오기, 백업·복구, 초대, 설치 안내, 관리자 전체 탭/진단, 도움말·법적 안내에 적용했다. 앱의 일반 펼치기는 공통 역할을 사용한다. 차트·시장 지표·다중행 지표 카드는 본래의 정보 위계를 유지한다. 기존 모든 화면의 장식·배치가 완전히 전환됐다는 의미는 아니다.

새 화면에서 로컬 버튼/입력 스타일을 복제하지 않는다. 배치(폭·여백·정렬)는 화면이, 동작의 글자·기본 높이·상태·초점은 공통 모듈이 담당한다. 특정 역할의 변경은 공통 모듈에서 하고 대표 화면의 두 테마와320/390/1440px를 확인한다.

`npm run lint:ui`는 일반 summary에 공통 펼치기 역할을 요구하고 로컬 인라인 스타일을 막는다. 다중행 사건/지표 카드에만 `data-ui-disclosure="composite"` 예외를 명시한다. 이 검사는 버튼 전체의 시각 품질까지 보장하지 않으므로 브라우저에서 동작·대비·넘침을 함께 검수한다. `verify`와 `prebuild`에서 실행한다.

## 상세 하단과 디자인 작업실 (2026-10-22 후속)

상세의 최근 소식은 확인 시각 → 기사 또는 빈 상태 → 다음에 확인할 것 순서로 읽는다. 미지원 거래일 브리핑은 지원 범위를 펼치는 짧은 안내로 두고 큰 빈 섹션을 반복하지 않는다. 자료 해석과 브라우저 비교 기록 안내는 한 펼치기에 모으며 데이터 누락·원인 미확인·저장 범위를 숨기지 않는다. 배경 개념은 크림색의 한 질문에서 시작하고 전체 개념은 펼쳐 읽는다. 추가 자료는 아이콘·제목·설명의 가벼운 목록으로 열며, 계산 도구는 이모지 대신 제목과 짧은 설명으로 다음 동작을 알린다.

디자인 작업실: `/design` (기존 `/brand-preview/design-system` 유지). 공통 CSS 색·글자·컨트롤과 승인된 그림을 직접 사용하며 StockReturnBrief·StockDetailResources·StockLearning·BuySimulator의 실제 컴포넌트를 배치한다. 상태 예시는 실제 종목 자료와 구분해 표시한다. 페이지 내부의 테마 전환은 저장된 서비스 설정을 바꾸지 않는다. 주비와 같은 도메인의 디자인 기준 페이지로 제공하며 독립 디자인 도메인은 사용하지 않는다.

## 아이덴티티와 적용 현황 (2026-10-22 보강)

[디자인 아이덴티티](JOOBI_DESIGN_IDENTITY.md)는 실제 서비스 로고·브랜드/의미 색의 구분, 숫자·여백·그림·문구·모션의 역할과 예외를 연결한다. 디자인 작업실은 실제 JoobiLockup과 공통 컴포넌트를 재사용하며 테마별 글자 대비, 상태 예시, 수동 점검표와 화면별 적용 현황을 제공한다. 체크 항목은 전체 서비스 검수 완료율이 아니며, 밝은 테마의 작은 상승·하락 글자와 기존 산업 그림·부가 화면·실기 검수는 남은 범위로 표시한다.

질문 영역은 흰 바탕의3개 질문에서 시작하고 추가 질문을 펼친다. AI 질문과 무료 개념 설명을 별도 동작으로 제공하며 로그인·횟수 안내는 목록 뒤에 둔다. 추가 질문에서 열린 답변·배경 설명은 목록을 접었을 때도 유지한다.
