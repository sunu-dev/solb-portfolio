# 주비 무료·유료 정책과 실제 지불의향 검토

기준일: 2026-07-18  
상태: 내부 가설 검증안, 판매·결제 비활성  
관련 문서: `PRO_TOOLS_INTERNAL_SPEC.md`

## 1. 결론

월 4,900원은 가격 자체가 비싸서 실패할 가능성보다, **현재 PRO 묶음이 매달 돈을 낼 만큼 절실하지 않아 실패할 가능성**이 더 크다.

- 기본 내보내기, 화면 프리셋, 광고 제거만으로는 반복 결제가 약하다.
- 사용자가 돈을 낼 가능성이 가장 높은 가치는 `실수 복구`, `변경 이력`, `여러 증권사 자료 일괄 정리`, `중복 방지`, `장기 기록`, `자동 월간 기록 묶음`이다.
- 타깃은 모든 투자자가 아니라 여러 증권사와 해외주식을 함께 관리하면서 엑셀·수작업에 시간을 쓰는 사용자다.
- “월 4,900원이면 쓰겠다”는 설문은 증거가 아니다. 가격이 표시된 시작 버튼, 실제 결제, 2개월차 유지 순으로 증거 강도가 올라간다.
- 법률·사업·결제 게이트 전에는 돈을 받지 않는다. 그전에는 가격이 표시된 가짜 문과 대기 신청까지만 측정한다.
- 첫 실제 유료 베타는 월간 요금제만 판다. 연간 결제는 2개월 유지가 확인된 뒤 도입한다.

따라서 현재 판단은 **조건부 GO**다. 도구형 PRO는 사업적으로 가능한 방향이지만, 지금 바로 결제 인프라부터 만드는 것은 이르다. 먼저 강한 유료 기능 두 개와 결제 행동을 검증해야 한다.

## 2. 영구 무료 기준

무료는 체험판이 아니라 주비의 완전한 기본 제품이어야 한다.

| 영역 | 무료 제공 기준 | 이유 |
|---|---|---|
| 투자정보 | AI 분석·시장 흐름·시세·투자 알림·종목 범위를 PRO와 동일하게 제공 | 투자정보 대가성 분리와 제품 신뢰 |
| 포트폴리오 | 기본 보유 관리와 기본 다중 증권사 통합 | 주비의 핵심 정체성 |
| 동기화 | 현재 상태의 기본 클라우드 동기화 | 기기 변경과 데이터 안전의 최소선 |
| 데이터 이동 | 기본 CSV·JSON 수동 내보내기 | 사용자 데이터를 인질로 잡는 인상 방지 |
| 기록 확인 | 현재 기록과 기본 기간의 이력 확인 | 무료 제품만으로도 지속 사용 가능해야 함 |

무료 사용자를 불편하게 만들어 결제를 유도하지 않는다. PRO는 불편 제거가 아니라 **반복 노동 자동화와 위험 절감의 추가 가치**를 판다.

## 3. PRO가 팔아야 하는 것

### 3.1 1순위: 자동 백업·버전 복구·변경 이력

사용자가 직접 입력한 평단가, 수량, 증권사, 메모가 잘못 바뀌거나 동기화 충돌이 났을 때 이전 상태로 되돌린다.

결제 이유:

- 데이터 손실 가능성을 줄인다.
- 어떤 값이 언제 바뀌었는지 확인할 수 있다.
- 여러 기기와 여러 증권사 기록을 관리할수록 가치가 커진다.
- 투자 판단이 아니라 기록 보존 서비스이므로 도구형 경계가 명확하다.

필수 구성:

- 최근 30일 자동 복구 지점
- 변경 전·후 차이 보기
- 한 번 누르는 복원과 복원 취소
- 월간 “이번 달 기록 보호 결과” 가치 영수증
- 복구 훈련과 실제 복원 성공률 관측

### 3.2 2순위: 여러 파일 OCR 일괄 정리·중복 확인

한 장씩 가져오는 무료 흐름은 유지하고, 여러 증권사 화면을 한 번에 읽어 종목·수량·평단가 중복을 확인하는 작업을 PRO로 둔다.

결제 이유:

- 반복 입력 시간을 눈에 보이게 줄인다.
- 여러 증권사를 가진 핵심 타깃에게만 강하게 작동한다.
- 처리 전후 시간을 비교해 가치 증명이 가능하다.

가드레일:

- OCR 결과는 자동 확정하지 않고 사용자가 변경 내용을 확인한다.
- 종목·수량·평단가 외 불필요한 이미지 원문은 최소 보관한다.
- 호출 비용 상한과 실패 시 재시도 정책을 둔다.
- 무료와 PRO의 투자 AI 품질 차등으로 설명하지 않는다.

### 3.3 3순위: 장기 이력과 자동 월간 기록 묶음

매월 말 포트폴리오 상태, 사용자가 입력한 메모, 변경 이력을 하나의 기록 묶음으로 보관한다.

중요한 점은 “이번 달 수익을 예측”하는 것이 아니라 “이번 달에 내 기록이 어떻게 달라졌는지”를 보여주는 것이다.

월간 가치 영수증 예시:

- 3개 증권사 기록을 한곳에 정리
- 변경 18건 저장
- 복구 지점 4개 생성
- 중복 후보 2건 확인
- 월간 기록 파일 생성 완료

이 영수증이 없으면 백업은 눈에 보이지 않아 사용자가 결제 가치를 잊기 쉽다.

### 3.4 보조 혜택

- 화면 구성 프리셋
- 기간별·변경 이력 포함 고급 내보내기
- 광고가 실제 도입된 경우 광고 제거

이 항목들은 핵심 결제 이유가 아니라 묶음의 완성도를 높이는 혜택이다.

## 5. 누가 실제로 돈을 낼 가능성이 높은가

### 높은 가능성

- 증권사 계좌가 2개 이상
- 보유 종목이 15개 이상
- 국내주식과 해외주식을 함께 보유
- 한 달에 두 번 이상 수량·평단가·메모를 갱신
- 엑셀이나 메모 앱으로 별도 기록
- 기기 변경이나 동기화 오류로 기록 손실을 걱정
- 거래내역 화면을 여러 장 가져오는 사용자

이 사용자의 결제 문장은 “더 좋은 종목을 알려준다”가 아니라 다음이어야 한다.

> 여러 증권사 기록을 다시 정리하는 시간을 줄이고, 잘못 바뀐 기록은 이전 상태로 되돌려요.

### 낮은 가능성

- 증권사 한 곳만 사용
- 보유 종목 10개 미만
- 증권사 앱에서 현재 평가금액만 확인
- 기록을 별도로 남기지 않음
- 월 1회 미만으로 주비에 방문

이 사용자에게 월 4,900원을 설득하려고 기능을 늘리면 제품이 복잡해진다. 무료 사용자로 유지하는 편이 낫다.

## 6. 가격 판단

### 6.1 4,900원은 가능한가

핵심 기능이 실제로 작동한다는 조건에서 가능하다. 다만 가격이 아니라 가치 묶음이 선행돼야 한다.

- `내보내기 + 프리셋`만 있으면 4,900원은 높다.
- `버전 복구 + 변경 이력 + 일괄 OCR + 월간 기록 묶음`이면 4,900원을 시험할 근거가 생긴다.
- 초기에는 월 4,900원 단일 요금제만 검증한다.
- 연 49,000원은 월간 유료 사용자의 2개월차 유지가 확인된 뒤 추가한다.
- 창업자 할인은 지불의향을 흐리므로 첫 20명 검증에서는 사용하지 않는다.
- 무료 체험 대신 기능 미리보기와 명확한 환불 기준을 제공한다. 무료 기본 제품이 이미 체험 역할을 한다.

### 6.2 단위 경제 가설

아래는 실제 결제사 견적이 아니라 의사결정용 시나리오다.

월 4,900원이 부가세 포함이라고 가정하면 부가세 제외 매출은 약 4,455원이다. 결제 비용을 결제액의 3.3%로 가정하면 약 162원이다.

| 유료 사용자당 월 변동비 가정 | 사용자당 월 공헌이익 추정 | 판단 |
|---:|---:|---|
| 300원 | 약 3,993원 | 충분한 여유 |
| 600원 | 약 3,693원 | 목표 시나리오 |
| 1,200원 | 약 3,093원 | 운영 가능하지만 OCR·지원 비용 개선 필요 |

월 고정비가 5만원이라면 약 13~17명의 유료 사용자가 기술 고정비를 덮는다. 다만 대표자의 시간, 세무·법률, 고객지원, 환불, 장애 대응 비용은 별도다. “서버비가 거의 없다”는 사실은 생존에는 유리하지만 사용자의 지불의향을 만들지는 않는다.

판매 전 실제 PG 수수료, 부가세 처리, OCR·저장공간·이메일 단가를 다시 넣어 계산한다.

## 7. 지불의향 검증 설계

### 단계 A: 문제 강도 인터뷰

대상: 높은 가능성 조건을 만족하는 12명.

먼저 기능을 보여주지 않고 묻는다.

1. 여러 증권사 기록을 마지막으로 합친 때는 언제인가?
2. 그때 어떤 파일과 앱을 몇 분 동안 사용했는가?
3. 기록이 틀리거나 사라져 다시 만든 경험이 있는가?
4. 지금 이 문제를 해결하기 위해 무엇을 쓰고 있는가?
5. 지난달 이 문제에 실제로 쓴 시간은 얼마인가?

통과 기준:

- 12명 중 6명 이상이 도움 없이 반복 문제를 설명
- 4명 이상이 월 20분 이상의 수작업 또는 기록 불안을 가짐
- 3명 이상이 현재 엑셀·유료 앱·별도 백업 같은 대안을 사용

이 기준은 시장 통계가 아니라 주비의 사전 의사결정 기준이다.

### 단계 B: 가격이 적힌 가짜 문

결제가 준비되기 전에는 실제 결제를 받지 않는다. 활성 사용자 중 핵심 타깃에게만 아래 제안을 노출한다.

> 주비 플러스 월 4,900원  
> 자동 백업·이전 기록 복구·여러 장 일괄 정리

버튼은 `월 4,900원으로 시작`으로 표시하고, 클릭 후 “현재 준비 중이며 결제되지 않는다”는 대기 신청 화면으로 연결한다.

측정 이벤트:

- `pro_offer_exposed`
- `pro_offer_opened`
- `pro_start_clicked`
- `pro_waitlist_submitted`

이벤트에는 종목명, 수량, 평단가, 자산금액을 넣지 않는다. 노출 위치, 가격안, 사용자 적격 조건, 시각만 기록한다.

대상 조건 예시:

- 증권사 라벨 2개 이상
- 보유 15개 이상
- 최근 14일 방문 2회 이상
- 가져오기 또는 기록 수정 2회 이상

사전 판정 기준:

- 적격 노출 100명 이상
- 시작 클릭률 12% 이상
- 대기 신청률 6% 이상
- 시작 클릭률 5% 미만이면 기능 묶음 재설계

가짜 문은 결제 의도가 실제 결제로 이어진다는 것을 보장하지 않는다. 다음 단계 진입 여부만 판단한다.

구현 상태(2026-07-19): 적격 사용자 판별, 로컬 14일 방문·관리 행동 집계, 가격 표시 카드·상세 모달·대기 신청, 인증 이벤트 API와 service-role 전용 DB 초안을 구현했다. 운영 노출은 `PRO_DEMAND_TEST_ENABLED`와 `PRO_DEMAND_POLICY_READY`가 모두 기본 비활성 상태이며, DB 마이그레이션까지 확인돼야 켜지는 fail-closed 구조다. `/admin`의 `PRO 준비` 탭에서는 이벤트를 기록하지 않는 미리보기를 볼 수 있다.

### 단계 C: 제한된 실제 유료 베타

법률·사업·약관·결제·복구 게이트를 모두 통과한 뒤 적격 사용자 20명에게 월 4,900원으로 제안한다.

강한 증거 순서:

1. 가격 페이지 열람
2. 결제 시작
3. 실제 결제 성공
4. 환불 기간 이후 유지
5. 두 번째 월 결제

사전 판정 기준:

- 초대 20명 중 실제 결제 5명 이상
- 결제자 중 4명 이상이 45일 시점에 유지
- 결제자 중 3명 이상이 핵심 유료 흐름을 사용하거나 월간 가치 영수증을 확인
- 환불률 10% 이하
- 유료 사용자당 월 고객지원 15분 이하
- 사용자당 공헌이익률 70% 이상

20명은 통계적 확정 표본이 아니다. 제품을 더 만들 가치가 있는지를 판단하는 초기 문턱이다.

### 단계 D: 가격 검증

첫 유료 베타가 통과한 뒤에만 3,900원·4,900원·6,900원을 서로 다른 신규 코호트에 순차 시험한다. 같은 사용자에게 임의로 다른 가격을 동시에 보여 불신을 만들지 않는다.

가격별로 비교할 것은 클릭률이 아니라 다음이다.

- 실제 결제율
- 2개월차 유지율
- 환불률
- 사용자당 공헌이익
- 핵심 유료 기능 사용률

매출은 `방문자 수 × 적격 사용자 비율 × 실제 결제율 × 월 가격 × 유지 개월`로 계산한다. 전체 가입자 대비 전환율 하나만 보면 핵심 타깃의 신호가 희석된다.

## 8. 제품에 반드시 넣어야 할 측정

퍼널:

`적격 사용자 → 제안 노출 → 상세 보기 → 시작 클릭 → 결제 시작 → 결제 성공 → 핵심 기능 사용 → 2개월차 유지`

기능별 가치 지표:

| 기능 | 가치 지표 |
|---|---|
| 버전 복구 | 복구 성공률, 복구 후 재수정률, 생성된 복구 지점 수 |
| 변경 이력 | 월간 변경 이력 확인률 |
| 일괄 OCR | 수동 입력 대비 절약된 단계, 중복 후보 확인 완료율 |
| 장기 기록 | 월간 기록 묶음 생성·열람률 |
| 고급 내보내기 | 예약 성공률, 파일 재다운로드율 |

결제 취소 사유는 정해진 선택지와 자유 입력을 함께 받는다.

- 쓸 일이 적음
- 무료 기능으로 충분
- 가격이 부담됨
- 기록 정확도를 신뢰하기 어려움
- 사용법이 복잡함
- 다른 서비스 사용
- 기타
