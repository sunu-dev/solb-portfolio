# 산업 연결 탐색 — 분류와 검수 범위

## 현재 범위 (2026-10-11)

- 탐색용 21개 산업 이야기와 별도로 **출처별 세부 업종 303개**(미국145·한국158)를 저장하고 검색·나라별 필터·관련 기업 탐색에 연결했다. 두 나라의 분류를 합쳐 단일 공식 표준이라고 부르지 않는다.
- 검색 카탈로그16,302종목 중 기업 분류 대상8,020종목, 연결7,947종목(99.09%), 미해결73종목이다. 연결 수는 기업 수가 아니라 종목 수이며 발행사 업종을 상속한 한국 우선주112종목과 상장폐지 이력15종목을 포함한다.
- 분모에서 펀드·상장지수상품7,310종목, 스팩382종목, 발행사 미연결 우선주·워런트·유닛·채권590종목을 분리했다. 미해결은 출처 없음60·원본 업종 없음5·공급자 충돌8이다.
- 세부 업종 **분류·예시 기업** 확대와 **독립 설명·그림** 확대를 구분한다. 독립 산업 이야기21개·공식 사업 근거 기업36개·설명71개이며, 새 업종 화면은 일치하는 기존 분야 그림(반도체·제약·조선 등)을 우선 쓰고, 나머지는 상위 산업 그림과 공통 비교/실적 질문을 재사용한다. 303개 맞춤 그림이나 전 업종 실시간 대장주 순위를 만든 것은 아니다.
- 상세 종목별 상태는 `artifacts/industry-coverage-20261011/coverage.json`, 미확인 개별 페이지 조회 결과는 `sources/industries/profile-supplement.json`에 보존한다. 종목명 변경으로 다른 티커에 리디렉션되면 자동 승계하지 않는다.

## 기업을 이해하는 설명 (2026-10-11)

- 업종 분류만으로 “어떤 회사인가요?”에 답했다고 간주하지 않는다. 실제 사업 요약을 먼저 제공하고, 자료가 없으면 “업종·종목 정보”로 범위를 표시한다.
- `companyStories.ts`의 상세 설명은 팔란티어·마이크로소프트·오라클 3개다. 사업 → 가상 사용 예시 → 고객 → 수익 구조 → 회사별 질문 → 투자 점검 관점 → 공식 근거로 이어진다.
- `CompanyBusinessExplanation`을 기존 산업 이야기와 전체 업종 목록에서 공유한다. 상세 자료가 없는 기업은 기존 36개 기업의 검토된 사업 설명 또는 거래소 주요 제품 정보를 재사용한다. MSFT는 기존 36개와 겹친다.
- 회사별 질문은 화면 안에서 펼쳐 읽으며 AI 생성이나 사용 횟수 차감이 없다. 7,947개 분류 종목 모두에 상세 설명을 작성한 것은 아니다.

## 분류 원칙
- 주요 산업 전체를 11개 대분류로 나누고 10개 세부 분야를 연결한다. 주비의 탐색용 분류이며 공식 분류 라이선스나 최신 업종 순위를 제공하는 기능은 아니다.
- `src/lib/sectorExploration.ts`에 산업명·상위 산업·대표 기업·역할·사업 출처·질문·연결 산업을 둔다. 화면에 반도체 전용 분기를 추가하지 않고 산업 자료로 렌더링한다.
- 확인한 36개 기업은 사업 역할로 연결하며, 복수 산업에 속할 수 있다. 예: 한화에어로스페이스 → 방산·항공우주·산업재.
- 미등록 종목은 저장된 업종 자료를 우선 사용하고, 없을 때 기존 fundamentals의 sector/industry를 분류표에 매핑한다. 펀드·스팩·별도 증권·자료 충돌은 일반 기업 업종으로 추정하지 않는다. 직접 거래 관계를 주장하지 않는다.
- 업종을 확인할 수 없으면 미확인 상태를 유지하고 모든 산업 탐색 목록을 제공한다. ETF를 특정 회사의 사업처럼 임의 분류하지 않는다.
- 모든 상장사의 세부 사업·모든 하위 산업을 조사 완료했다는 의미가 아니다. 대분류 커버리지와 기업별 근거 커버리지는 구분한다.

## 자료·화면 범위
- 기존 11개 주제와 신규 20개 분류별 3개 주제, 총 71개 설명을 제공한다. 반도체는 기존 설명을 재사용한다.
- 출처는 기존 확인 자료와 새로 읽은 기업 공식 사업 소개다. 새 사업 소개의 확인일은 2026-10-10. 확인일이 분기 실적의 기준일이라는 뜻은 아니다.
- 당일 변동 원인·최신 계약·시장 점유율·실시간 대장주 순위를 자동 수집하지 않는다. 설명을 읽는 동안 AI 요청이나 계좌 쓰기, 분석 횟수 차감이 없다.
- 산업별로 용어 → 전달 과정 → 관련 기업 → 다음 확인 항목 → 다른 산업으로 이어진다. 일반 대장주 설명에서 반도체 예시를 강제하지 않는다.
- 원래 설명으로 돌아가기와 새 탭 종목 상세를 지원한다. 읽은 설명은 현재 컴포넌트의 브라우저 메모리에만 남는다.

## 검수 방식
- `artifacts/sector-expansion-20261010/manifest.json`: 20개 검수 출발점.

- 가상 사용자와 시세 응답을 사용하고 모든 API 및 외부 요청을 차단/대체한 격리 Chrome 검수다. 실제 계정·실시간 시세·외부 AI·실기기 Safari 검수와 구분한다.

## 추가 산업을 넣는 법
1. 기존 대분류 아래 세부 분야를 정하고 제품·고객을 설명할 공식 자료를 읽는다.

- 실제 로컬 `/api/fundamentals?symbol=BE` 응답에서 sector·industry가 null임을 확인했다. 기존에는 검토된 기업에도 없어 산업 미확인 상태가 됐다.

## 업종 자료 갱신과 품질 검사

1. `node scripts/update-stock-catalog.mjs`로 검색 목록의 기준일을 맞춘다.
2. `node scripts/update-industry-catalog.mjs`로 Stock Analysis 일괄 자료, KRX KIND, KIS 종목 마스터를 대조한다. 업종 원문은 `sources/industries/*-taxonomy.tsv`에서 한국어 표시명·탐색용 대분류에 연결한다.
3. `node scripts/audit-industry-coverage.mjs`로 실제 분류 함수와 검색 목록을 조인한다.
4. 누락된 미국 종목은 `node scripts/update-industry-supplement.mjs`로 정확한 코드의 공개 회사 페이지를 확인한 뒤 2~3단계를 다시 실행할 수 있다. 개별 근거는 확인일부터30일만 갱신 입력으로 유효하며 날짜를 임의 연장하지 않는다. 티커가 바뀐 페이지·404·빈 업종은 실패 사유로 남긴다.
5. 헤더·최소 수량·미등록 업종·20% 초과 분류 감소를 검사하고 실패하면 기존 산출물을 건드리지 않는다. 두 JSON을 먼저 준비하고 파일별 rename으로 교체하며, 둘 사이 프로세스 중단은 검사에서 기준일 불일치로 잡는다. 두 파일을 하나의 트랜잭션으로 저장하는 구조는 아니다.
6. 전체 종목 사전은 서버 route에만 import하고 브라우저에는 업종 목록·최대3개 예시만 전달한다. Yahoo 실패 시에도 분류를 반환하고 미확인 가격·재무 지표는 null로 유지한다.

미국 예시 기업은 원본에 제공된 시가총액 순서, 한국 예시는 회사명 순서이며 화면에 선정 방식을 공개한다. 상장폐지 이력이 있는 종목은 관련 기업 예시에서 제외한다. 한국 우선주 업종 상속은 공식 코드와 발행사명이 모두 일치할 때만 허용한다.

기업 예시는 동일한 원본 회사명을 중복 제거해 A주·B주가 두 기업처럼 나오는 것을 막는다. 업종 → 기업 → 질문 → 이전 설명 경로는 동일한 탐색 이력에 저장해 원래 기업으로 복귀한다.
