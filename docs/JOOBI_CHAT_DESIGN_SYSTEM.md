# 주비 채팅 디자인 시스템 v2

작성일: 2026-11-05 · 적용 대상: 모든 종목 상세와 공통 주비 질문창

## 목적
초보자가 보고 있는 종목을 주비와 함께 이해한다. 설정 양식을 채우는 화면이 아니라, 질문하고 읽고 다시 묻는 화면으로 만든다. 캐릭터는 답하는 주체와 진행 상태를 알려주며 장식으로 반복 배치하지 않는다.

## 화면 구조
1. 고정 헤더: 선택한 주비 캐릭터, 질문창 제목, AI 주식비서 표시, 닫기.
2. 대화 맥락: 종목명, 비교 기간, ‘대화 설정’. 설정은 기본적으로 접힌다.
3. 대화 본문: 처음에는 짧은 인사와 예시 두 개. 이후 시간순 질문·답변. 본문만 스크롤한다.
4. 고정 입력: 다음 질문, 남은 횟수, 전송 또는 기다리기 중단. 상세 전송 범위는 펼쳐 읽는다.

## 실제 코드와 토큰
- 구현: `src/components/learning/JoobiChat.module.css`, `JoobiAssistantLauncher.module.css`.
- 글꼴: 공통 `--font-ui`. 본문16px, 입력16px, 설정12px, 헤더20px(모바일18px). 좁은 화면에서도 입력 자동 확대를 피하도록16px을 유지한다.
- 색상: `--surface`(읽기 바탕), `--bg-subtle`(설정·비활성 배경), `--text-primary`/`--text-body`/`--text-secondary`(정보 위계), `--brand-fill`와`--on-brand-fg`(내 질문·선택·전송). 임의의 채팅 전용 색상 체계를 추가하지 않는다. 공통 다크 토큰을 따른다.
- 로컬 규격: `--chat-control-radius:12px`, `--chat-input-radius:18px`, `--chat-body-size:16px`, `--chat-label-size:12px`, `--chat-touch-size:44px`.
- 여백: 큰 화면 좌우24px, 모바일16px. 본문 질문·답 묶음 간28px. 설정 내부16px, 항목 간16px.
- 주비 답은 긴 말풍선 테두리로 가두지 않는다. 내 질문은 오른쪽 브랜드색 말풍선, 주비 답은 캐릭터·이름 아래 왼쪽 본문이다.

| 일정 안내 | 새 안내는 맥락에 맞는 곳에 표시. ‘확인했어요’ 뒤에는 다시 보기로 접고 진입 버튼의 반복 안내도 멈춘다. |

## 접근성과 작은 화면
- 인터랙션은44px 이상을 기본으로 하고 키보드 포커스를 표시한다. summary도 focus trap에 포함하며 접힌 내부 요소는 제외한다.
- 모바일 본문은 독립 스크롤, 입력은 하단. modal viewport 계산을 재사용한다.
- 다크 모드는 색상쌍 토큰을 사용한다. 움직임 줄이기 설정이면 대기 애니메이션을 정지한다.
- 모바일 실제 가상 키보드, 다크 배포 화면, 로그인 연속 대화는 별도 실화면 검수 기록을 남긴다. CSS 구현만으로 통과했다고 하지 않는다.

## 전송·내 종목 선택 보완 (2026-11-05 오후)
- 첫 보내기를 누르면 아래에 별도 동의창만 생겨 무반응처럼 보인다는 실제 사용자 결함을 수정했다. 처음부터 전송 범위를 보여주고 단일 ‘동의하고 보내기’를 사용한다. 이후는 ‘보내기’.
- API 전송 전에는 동의를 추정하지 않는다. 텍스트에서 Enter만 누르면 최초 동의 버튼으로 포커스를 안내한다.
- 실패 문구는 입력창 바로 아래에 둔다. 답변 영역의 스크롤 바깥에 숨기지 않는다.
- 등록한 실제 보유·관심 종목을 입력창 가까운 빠른 선택에 표시한다. 샘플은 제외하고 중복 티커는 합친다. 첫4개와 전체 선택을 제공한다.
- 선택한 종목은 입력창 위에서 다시 확인한다. 다른 종목의 대화 이력을 섞지 않고, 비어 있는 대상 초안에는 작성 중 질문을 복사한다. 이미 대상 종목 초안이 있으면 이를 덮어쓰지 않는다.
- 등록 목록·수량을 API에 자동 전송하지 않고 사용자가 선택한 종목만 기존 요청에 넣는다.

## 연결 대기와 오류 복구 (2026-11-05)
- 시작 대기·지연·실패 화면에도 설정한 주비 캐릭터를 재사용한다. 같은 배치에서 상태와 재시도만 바꾸며 장식적인 시장 격언으로 연결 상태를 대신하지 않는다.
- 질문 연결 오류를 횟수 부족으로 설명하지 않는다. 세션 조회, 통신, 시간 초과, 응답 표시 오류를 구분하고 질문을 보존한다. 응답을 받지 못하면 사용량을 재조회하며 자동 재전송하지 않는다.

## 모바일 키보드와 진입점 (2026-11-05)
- 모바일 우하단 진입점은60px 캐릭터 아이콘만 표시하고, 긴 일정 안내는 질문창 안에서 읽는다. 버튼의 접근 가능한 이름은 유지한다.
- 키보드가 차지한 공간을 제외한 실제 보이는 영역에 창의 위치·높이를 맞춘다. 내용이 넘치면 창 내부에서 읽거나 입력할 수 있어야 하며 전송 영역을 단순히 잘라내지 않는다.
- 좁아진 실제 창 높이에 따라 헤더와 입력 여백을 줄인다. 화면 전체 높이 기준의 반응형 규칙만으로 키보드 대응을 판단하지 않는다.


## 2026-11-06 작은 화면 보완
- 등록 종목 행은 입력 테두리 바깥에 둔다. 입력과 전송은 같은 줄이며 작성한 길이만큼 입력 높이를 늘린다.
- 입력 전체의 굵은 이중 테두리를 제거한다. 얇은 중립색 포커스와44px 전송 터치를 유지한다.
- 최초 전송 버튼은 ‘동의하고 보내기’를 유지한다. AI로 보내는 범위를 짧은 펼침 안내로 제공해 작은 화면에서 본문을 밀어내지 않는다.
- 전송을 시작하면 입력 포커스를 풀어 모바일에서 키보드를 내린다. 다음 질문을 작성 중일 때 답변 도착이 그 입력을 지우거나 포커스를 빼앗지는 않는다.
- 기본 전송은 접근 가능한 이름이 있는 위쪽 화살표 버튼이다. 남은 횟수는 입력 상자 아래에 배치한다.

## 2026-11-06 펼친 답변까지 같은 디자인 적용

- AskJoobi는 LearningDesk의 과거 페이지용 답변 스타일을 가져오지 않는다. 답변/근거/비교/출처/후속 질문은 JoobiChat.module.css의 같은 글자·간격·색상 규칙을 쓴다.
- 비교 카드 내부 여백 14px, 제목 14px, 행 이름13px, 숫자17px, 보조설명12px. 기존24px바깥여백/20px안쪽여백/22px숫자로 갑자기 크기가 바뀌던 구성을 제거했다.
- 비교 대상이 있으면 “같은 기간의 움직임”, 하나뿐이면 “가격 변화”. 기준일 종가와 마지막으로 받은 가격을 구분한다. 낮은 가격이 전일 종가와 같은 0% 경우도 정확하게 표현한다.
- 가격 하락/상승은 공통 loss/gain 토큰과 부호로 함께 표시한다. 숫자색만으로 의미를 전달하지 않는다.
- 근거/출처의 펼친 상태, 출처 없음, 여러 비교 행, 후속 질문, 에러, 이용 횟수 소진도 디자인 검수에 포함한다.
- “아래 내용 더 보기”는 읽는 영역 아래의 별도 공간에 놓아 본문을 덮지 않는다. 입력창은 계속 접근 가능하게 둔다.
- 첫 전송 버튼은 “물어보기”. 근처에 AI 전송 정보를 안내하고 실제 클릭으로만 기존 전송 동의 처리를 수행한다. Enter만으로 최초 동의를 대신하지 않는다.
- 읽은 거래시간 안내는 다시 펼칠 수 있지만 자체 하단선을 남기지 않는다. 메인 평가손익 구획선과 겹치지 않게 한다.
- 화면 검수용 고정 응답과 실제 AI 응답 검사는 구분해 보고한다. fixture를 실제 시황 답변이나 품질 개선의 근거로 쓰지 않는다.

## 2026-11-10 검수 반영

- 대화 대상·기간은 상단 한 줄로 유지한다. 시장 전체 대신 한국 시장/미국 시장을 표시한다. 질문에서 서버가 다른 종목을 확인한 경우 실제 답변 대상을 본문에 안내한다.
- ‘변경’과 ‘전송 안내’는 대화 영역을 대체하는 별도 패널로 연다. 설정 안에서 종목·시장·기간 및 내 종목 바로 선택을 제공한다. Escape/돌아가기 후 초안과 대화를 유지한다.
- 입력부에 전체 종목 행과 긴 고지를 반복하지 않는다. 처음 보내기 전 전송 요약 한 줄과 상세 안내 진입을 제공한다. 최초 Enter로 동의를 추정하지 않는다.
- 모바일 질문창은 가용 화면 너비와 높이를 사용한다. 읽기 영역만 스크롤하며 입력부는 아래에 유지한다. 전체 대화 기록을 줄여 공간을 확보하지 않는다.
- 긴 답변은 문장 경계로 문단을 나눈다. 원문 숫자·조건·유보 표현을 생략하거나 재작성하지 않는다. 이 처리는 모델 답변 정확성 개선을 의미하지 않는다.
- 검증 근거: `artifacts/chat-polish-20261110/chat-flow.json`. API 오류·재시도는 격리 응답으로 검증하며 실제 모델 답변 품질 측정과 구분한다.

## 2026-11-11 갱신 — 덜어내기와 숫자 먼저
사용자 요청(토스 같은 사용 경험, AI 같지 않은 내용·디자인, 첫 답 지연 단축)에 따른 변경이다.
- **질문 제안 줄(`.suggestion`)**: 첫 화면 예시와 답변 뒤 이어 묻기가 같은 모양을 쓴다. 너비가 제각각인 회색 상자와 글 뒤 꺾인 화살표를 없애고, 폭을 맞춘 흰 줄·얇은 테두리·오른쪽 화살표 하나로 통일했다. 첫 화면에는 작은 안내 ‘이렇게 물어볼 수 있어요’를 둔다.
- **등락률 띠(`.priceStrip`)**: 가격 움직임을 묻는 질문(왜 움직였는지, 요즘 어떤지, 시장에 무슨 일이 있었는지)에만 쓴다. 답을 기다리는 동안 먼저 나타나고 답변 맨 위에 그대로 남는다. 바로 위 답변에 같은 숫자가 있으면 반복하지 않는다. 매수·매도 고민에는 그날의 등락률을 앞세우지 않는다. 띠가 있으면 대상·거래일 줄과 접힌 비교 표의 같은 숫자는 생략한다.
- **반복 줄이기**: 같은 종목·거래일의 대상 표시, 용어 안내, 후속 질문 아래 설명 문장을 답마다 되풀이하지 않는다.
- **인사·감사·맞장구**: AI에 보내지 않고 화면에서 바로 답한다. 자료·피드백·횟수 표시를 붙이지 않는다.
- **입력**: 마우스·키보드 환경에서는 질문창을 열면 바로 적을 수 있다. 터치 기기에서는 화면 키보드를 자동으로 열지 않는다.
- 확인 범위: 로컬 Chrome 게스트(밝은·어두운 화면, 340px 폭 줄바꿈). 실제 좁은 화면과 로그인 전송 흐름은 미확인.


## 2026-11-13 첫 질문 말풍선
사용자 요청으로 첫 예시2개는 폭이 내용에 맞는 둥근 말풍선, 작은 대화 아이콘, 부드러운 노랑/회색 바탕으로 변경. 후속 질문 목록은 유지. 누르면 입력만 채우고 자동 전송하지 않음. 공통 색 토큰/44px 이상 터치/키보드 포커스 유지. 실화면 검수는 별도.
