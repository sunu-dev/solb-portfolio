# 투자 기록 비공개 보관 — 구현과 전환 기준

2026-10-30. **격리 구현·검증 중. 운영 화면/동기화 미연결, 운영 DB 변경 없음.**

사용자가 이 작업을 이번 목표로 지정했다. 기존의 ‘서버·운영자가 사용자 키를 갖지 않음’ 요구를 유지한다. 카카오 로그인만으로 풀 수 있는 서버 키 방식으로 요구를 낮추지 않는다. 현재 운영은 기존 JSON 저장이며 새 보호 수준을 홍보하지 않는다.

## 키와 사용자 경험의 방향

카카오 로그인은 계정을 확인하고, 패스키는 투자 기록을 여는 별도의 역할을 한다. 패스키의 PRF 확장으로 얻은 32byte 출력을 기기 안에서만 사용한다. 복구키를 종이에 적는 방식을 기본으로 요구하지 않는 후보 구현이다.

- 처음 설정: 패스키 생성 → 실제 잠금 해제 호출 → 투자 기록 암호화 → 저장할 키 포장본을 다시 열어 같은 기록을 복호화하는지 검증.
- 돌아온 기기: 카카오 로그인 → 기기의 잠금 확인 → 투자 기록 복원. 일반 로그인과 복호화를 혼동하지 않는다.
- 새 기기: 같은 패스키를 사용할 수 있고 PRF 결과가 재현되는지 실기로 검증해야 한다. 동기화된 패스키/기존 기기 인증의 지원 범위가 아직 검증되지 않았다. 모든 Apple·Google 기기에서 자동 복원된다고 약속하지 않는다.
- 미지원·취소·키 분실: 평문이나 서버 마스터키로 우회하지 않는다. 보호 기능 설정을 완료하지 않고 이유와 가능한 경로를 설명한다. 모든 복구 수단을 잃으면 주비가 대신 풀어줄 수 없다는 점을 설정 전에 알려야 한다.

기기의 얼굴·지문·잠금 확인은 운영체제/인증기가 담당한다. 코드에서 PRF 출력이나 credential 응답 전체를 JSON으로 만들어 서버에 보내지 않는다. 이 모듈은 로그인 인증 서버의 서명 검증을 대신하는 용도가 아니다.

근거: [W3C WebAuthn PRF](https://www.w3.org/TR/webauthn-3/#prf-extension)는 자격 증명과 연결된 대칭키 재료를 얻는 용도를 설명한다. 표준 존재와 실제 기기 호환성은 별도로 검증한다.

SQL은 **migrations 폴더에 넣지 않았다.** 별도 검토 없이 자동 적용하거나 운영에 복사하지 않는다. 제안 스키마에서도 비공개 rollout 표의 사용자별 허용이 없으면 전환/쓰기가 비활성이다. 일반 사용자와 service-role은 허용 표를 변경할 수 없다. 읽기는 쓰기 중단 후에도 유지한다.

롤아웃 허용 표는 외부 검토·데이터 전환 준비를 자동 검증하는 시스템이 아니다. 지금 운영에서 사용자를 허용하면 준비되지 않은 경로가 남는다. SQL만 적용하면 출시 준비가 끝나는 구조로 해석하지 않는다.

### 독립 검증용 reader 설정 — 아직 켜지 않음

`NEXT_PUBLIC_PORTFOLIO_VAULT_READER=on`은 현재 개발 중인 클라이언트 전환용 설정이다. 기본 꺼짐이며 사용자 허용 권한은 아니다. 현재는 평문 저장 차단까지만 연결했으므로 **이 설정만 켜서 배포하면 안 된다.** 잠금 화면·암호화 내구 저장·로그아웃 인계·기존 자료 정리가 완성되기 전에는 활성화하지 않는다.

보호 표시를 확인한 브라우저는 owner가 비거나 설정이 꺼져도 평문 저장으로 돌아가지 않는다. 원래 `solb-portfolio-storage`는 검증된 전환 전까지 그대로 두고 화면 설정 네 가지만 별도 저장한다. 이 처리는 기존 평문을 삭제/암호화한 것이 아니며, 보호 표시가 없는 새 기기의 서버 상태 확인도 대신하지 않는다. 새 기기에서 서버 `sealed` 상태를 확인하고 기존 빈 계정 판정을 막는 연결이 여전히 필요하다.

`portfolioVaultRuntime.ts`와 실제 Zustand adapter, 공유 handoff를 추가하고 `useAuth`의 로그아웃/계정 전환에 연결했다. 서버 응답을 기다리지 않고 최신 편집을 암호화 outbox에 보관한 뒤 키·메모리를 닫는다. 저장 실패 시 인계를 중단하고 재시도할 기록을 유지한다. 인증 callback은 동기적으로 반환하고, 로컬 보관 완료 뒤 가장 최신 계정 이벤트만 적용한다.

아직 홈에서 runtime을 생성하거나 잠금 해제/이관 화면을 제공하지 않는다. 새 reader 설정은 계속 꺼둔다. 다음 작업은 서버 sealed 상태 확인, 기존 로컬 사본 대조, 잠금 해제 화면과 runtime 활성화 연결이다. 실제 기기·Supabase REST/JWT 검증 전에는 운영 적용하지 않는다.

## 전환 전에 반드시 연결할 경로

1. **화면과 기존 훅**: `usePortfolioSync`, Zustand persist, 편집/가져오기/복구 UI를 새 controller와 연결한다. 보호 계정이 옛 저장 함수로 빠지지 않게 한다. 구버전 탭에는 갱신/잠금 상태를 안내한다. 현재의 빈 종목 판정으로 보호 계정을 신규 계정으로 오인하면 안 된다.
2. **모든 로컬 사본**: 기존 outbox·`solb-portfolio-storage`·`solb_portfolio_recovery_v1:`·메모/사용자별 저장을 조사한다. 소유자가 없는 옛 기록을 현재 로그인 계정에 임의 귀속하지 않는다. 새 암호문을 열어 비교하고 내구 저장을 검증한 뒤 해당 사본만 정리한다. 실패하면 전환을 중단하고 원본을 보존한다.
3. **전환 도중 종료**: DB 전환 뒤 브라우저 정리가 실패해도 평문 저장으로 되돌리지 않는다. 암호화가 완료된 서버 기록과 아직 남은 로컬 사본을 구분해 이어서 정리한다. 현재 proposal은 서버 활성 행 전환만 담당한다.
4. **알림과 발송 사본**: morning-brief/check-alerts/monthly-d3의 서버 평문 계산을 바꾼다. 보유 종목/손익을 넣지 않은 공통 알림과 기기에서 여는 개인 화면을 우선 검토한다. 대기·재시도·이미 lease를 얻은 발송 작업까지 멈추거나 완료 상태를 확인한 후 전환한다. 단순 사전 플래그 조회는 발송 중 전환과의 경쟁 조건을 해소하지 않는다.
5. **백업과 외부 사본**: DB/WAL/과거 백업, digest 본문, 이메일/푸시 업체, 문의 webhook, 공유 OG URL, 수동 파일을 대조한다. 기존 사본의 삭제/보존 만료 전에는 과거 기록까지 모두 보호됐다고 표현하지 않는다.
6. **운영 방어**: 운영 계정 MFA/복구·최소 권한·배포 권한·CSP·공급망·사고 대응을 검증한다. 사용자 기기의 악성 확장이나 악성 웹 코드 배포는 저장 암호화만으로 해결되지 않는다.
7. **독립 검토와 실제 기기**: 자체 테스트와 가상 인증기는 독립 보안 검토/실기 복구를 대체하지 않는다. 기기를 모두 잃거나 플랫폼 계정 복구에 실패하는 경우를 포함한다.

## 검증 범위

현재 근거는 [격리 검증 보고서](../artifacts/portfolio-vault-rollout-20261029/REPORT.md)를 따른다. PostgreSQL의 역할/RLS/RPC 검증, Chrome의 실제 Web Crypto·WebAuthn/가상 인증기, IndexedDB와 연결 흐름을 구분해서 기록한다. 실제 Supabase REST/JWT·제품 화면·물리 기기 통합 완료로 합산하지 않는다.

서버의 revision은 CAS 충돌을 막지만 악의적인 서버의 전체 롤백을 완전히 증명하지 못한다. 기기에 신뢰할 수 있는 더 높은 revision이 남아 있을 때 오래된 응답을 거부하며, 새 기기에서 그 기준까지 없는 경우의 신선도는 별도 한계다. 서버에 의한 삭제/서비스 거부도 별개다.
