## 결과와 범위

## 원인

- 같은 조사에서 Finnhub는 565ms, Yahoo는 433ms에 응답했으나 Supabase `api_calls` 읽기는 35초를 초과했다.
- 공통 `defineRoute`가 처리 전 호출 수 조회와 응답 전 기록 저장을 제한 시간 없이 기다렸다. 공개 시세와 경제일정도 DB 지연을 그대로 받았다.
- 집계·서버 로그에서 service-only 테이블에 인증용 anon 클라이언트를 사용한 오류도 확인했다. 기존 서버 클라이언트 원칙에 맞게 수정했다.
- 시세는 종목·지수 묶음 전체를 기다렸다. 경제일정은 여러 공식 일정·FRED·실적 자료와 캐시 응답에 충분한 상한이 없었다.

## 변경

- 호출 수 조회와 기록 저장은 각각 1초까지 기다린다. `AbortSignal`과 promise deadline을 함께 적용한다.
- 두 공개 라우트의 기록 저장은 Next.js `after()`에서 수행한다. 인증과 호출 제한 판단은 응답 전에 유지한다.
- DB가 늦거나 불가할 때는 요청을 먼저 예약하는 서버 인스턴스별 제한을 유지한다. 정상 DB의 공유 집계도 계속 검사한다. **장애 중 인스턴스별 제한은 여러 인스턴스에 걸친 전역 한도를 보장하지 않는다.** 기존 무조건 허용보다 강화했으며, 별도 AI 일일 사용량·인증·결제 처리는 바꾸지 않았다.
- Finnhub 1.5초, Yahoo 2.5초로 제한하고 기존 공급자 대체 경로를 유지한다. 한국 숫자 코드는 두 거래소 후보를 병렬 조회한다.
- 브라우저에서는 종목과 시장 지수를 분리해 먼저 받은 시세를 표시한다. 동일한 진행 중 요청을 공유하되 실패나 오래된 시세를 새 결과로 캐시하지 않는다. 배치 요청은 9초 제한이다.
- 경제 자료 fetch는 본문까지 4.5초, 캐시를 포함한 출처별 호출은 5.5초 제한이다. 성공한 자료를 보존하고 실패한 일정은 기존 목록의 확인 날짜를 명시한다. 미확인 발표 수치는 만들지 않는다.
- 종목별 실적 추가 전 공통 일정 배열을 복사해 다른 요청에 종목 일정이 섞이지 않게 한다.
- 불완전 경제일정은 CDN 캐시하지 않으며 브라우저 캐시는 30초로 줄인다. 다시 시도는 해당 캐시를 지운다. 정상 브라우저 캐시는 5분 유지한다.
- `Server-Timing`에 제한 검사와 본문 처리 시간을 구분해 남긴다. POST 시세 응답의 실효성 없는 CDN 캐시 지시는 제거했다.
