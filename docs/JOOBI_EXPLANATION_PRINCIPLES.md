# 주비의 제품 및 설명 원칙

## 개인 주식비서와 대화를 이어가는 경험 (2026-11-05)
- 채팅 디자인과 상태별 동작은 [주비 채팅 디자인 시스템](JOOBI_CHAT_DESIGN_SYSTEM.md)을 따른다. 설명을 쉽게 줄일 때 개념의 범위를 줄이거나 한 종류의 특징을 전체의 특징으로 바꾸지 않는다.
- 같은 탭에서 종목·시장·기간별 대화와 초안을 이어가되 보관 범위와 전송 범위를 구분한다. 읽은 일정 안내는 사용자가 확인한 뒤 접고, 다음 변경은 별도로 알린다.
- 사용자 재확인: 질문을 제출하고 결과를 받는 폼을 넘어, 내 상황을 아는 개인 주식비서와 이야기를 주고받는 경험이 목표다. 캐릭터·말풍선만으로 달성했다고 판단하지 않는다.
- 보고 있는 종목과 현재 대화의 맥락을 연결하고, 후속 질문에 앞의 답을 반복하지 않고 새 궁금증에 답한다. 실제로 전달·보관하지 않은 과거 대화나 투자 정보를 아는 척하지 않는다.
- 보낸 질문, 답변 대기, 주비의 답, 이어 쓰는 질문의 위치를 명확히 구분한다. 답변이 도착해도 사용자가 쓰던 다음 질문을 지우거나 입력 포커스를 빼앗지 않는다.
- 설정과 근거는 필요할 때 펼치고, 질문과 답을 읽는 흐름을 우선한다. 전송 동의와 이용 횟수는 사용자가 판단할 수 있게 제공한다.
- 대화 기억 범위·닫은 뒤 보관 여부·중단 시 횟수 처리는 실제 동작대로 안내한다. UI 검사와 실제 여러 차례 대화의 내용 검증을 구분한다.

## 차트 해설의 역할 (2026-11-04)
- 첫 가격·마지막 가격·최저·최고를 다시 읽어주는 설명으로 AI 이용 횟수를 쓰게 하지 않는다. 수치 계산과 단순 사실은 코드가 제공한다.
- 추세·평균선, 이전에 돌아선 가격, 거래량, 변동 폭, 가격 변화의 크기, 봉의 모양 등에서 현재 자료로 의미 있게 비교할 수 있는 관점을 고른다. 특정 지표 하나를 모든 종목에 고정하거나 지표를 전부 나열하지 않는다.
- 관찰한 근거 → 이 차트에서의 의미 → 다음에 비교할 변화 순서로 설명한다. 같은 가격에서 만든 여러 지표를 독립된 확인 증거로 합산하지 않는다.
- 이전 고점·저점의 모양과 마지막 가격을 구분한다. 저점 위로 잠시 올랐다는 이유로 하락 흐름 종료라고 하거나, 작은 가격 차이 하나로 상승 흐름 종료라고 단정하지 않는다.
- 해설과 차트에 같은 자료와 지표를 사용한다. 5분봉20개와20일선을 구분하고 자료가 적은 지표·기간·전망을 만들지 않는다. 용어 뜻과 계산 근거는 읽던 자리에서 펼쳐본다.
- 계산·검사 통과가 실제 문장 정확성이나 사용성의 증명이 되지는 않는다. 실제 응답에서 수치 관계·비교 기간·문장 이해를 함께 확인한다.

## 직접 질문·내 주식사전·선택 복습 (2026-11-04)
- 사용자가 직접 질문하고, 궁금한 용어를 모으고, 모은 용어로 퀴즈를 풀기를 명시적으로 요청했다. 복습은 선택 기능이며 설명을 읽는 조건으로 만들지 않는다.
- 질문에는 선택한 종목의 서버 공개 자료와 용어 설명을 연결한다. 보유 수량·평균 매수가·메모를 자동 전송하지 않는다. 직접 적은 질문과 헷갈리는 용어 전송은 입력창에서 별도로 확인한다.
- 로그인한 사전은 계정에 보관한다. 게스트 사전은 현재 브라우저에만 저장하며 로그인 계정으로 자동 이전하지 않는다. 저장 실패·동시 수정 충돌을 성공으로 표시하지 않는다.
- 복습 문제와 정답은 같은 출처 기반 용어 정의에서 만든다. 사용자 메모·미확인 단어를 정답 근거로 쓰지 않으며 의미가 겹치는 관련 용어를 오답으로 내지 않는다.
- 저장·퀴즈 정답·방문 빈도를 숙련도로 판정하지 않는다. 사용자가 직접 표시한 ‘아직 헷갈려요’는 설명 순서와 복습 우선순위에만 사용한다.
- 질문 이력과 AI 답변을 자동 검수 로그로 보관하지 않는다. 2026-11-07 사용자 승인: 유형·지연·실패를 원문 없이 집계하고, 사용자가 별도 동의해 제공한 질문·답변 사례만 30일 검수에 사용한다. 사례 미리보기·개인정보 제거·계정별 삭제·관리자 접근 제어를 적용한다. 저장·검색·복습에는 추가 AI 호출이나 예약 작업을 만들지 않는다.

## 고정된 제품 방향
사용자 확정: 2026-09-19. 기능 기획, 콘텐츠, 문구, 화면 구성의 공통 판단 기준이다.

- **정체성: 개인 주식비서.** 시장에서 일어난 일을 챙겨주고, 그 일이 사용자의 투자와 어떻게 이어지는지 설명한다.
- **핵심 타깃: 주식 초보자.** 금융 용어나 티커를 이미 안다고 가정하지 않는다. 익숙한 한국어와 생활 속 예시로 설명한다.
- **서비스 목표: 오래 머무르고 다시 찾는 경험.** 읽을수록 이해가 쌓이고 자신의 투자에 필요한 정보를 발견해, 지속적으로 이용할 이유를 만든다.
- **사용성 기준: 토스증권.** 사용자 확정(2026-10-02): 편안함, 깔끔한 화면, 정보 전달의 쉬움은 최소 비교 기준이다. 주비는 이를 갖추고 시장 변화와 내 투자 사이의 관계를 더 잘 이해하게 만드는 경험을 목표로 한다. 이 기준을 문서화했다고 경쟁 서비스보다 우수함이 검증된 것은 아니다.
- **차별화의 중심: 연결해서 보는 눈.** 사용자 확정(2026-10-02): 피터 나바로의 『브라질에 비가 내리면 스타벅스 주식을 사라』는 글로벌 변화에서 경제·산업·기업을 거쳐 투자로 이어지는 탑다운 사고의 은유다. 특정 날씨나 종목 하나의 고정 규칙으로 축소하지 않는다. 이해한 내용을 사용자가 다른 사람에게 자신의 말로 설명할 수 있게 돕는다.
- **예시는 의도를 이해하는 단서다.** 사용자 정정(2026-10-02): 위 책과 커피 이야기는 제품의 대표 콘텐츠를 지정한 것이 아니다. 사용자가 든 예시를 그대로 화면·홍보 문구로 옮기지 않는다. ‘남에게 설명할 만큼 이해한다’는 목표도 퀴즈나 설명 작성 과제를 요구한다는 뜻이 아니다. 실제 사용 맥락에서 필요한 해설을 제공한다.

## 기능과 화면의 판단 기준
- 개선의 목적은 실제 이용자의 문제 해결이다(2026-11-03 사용자 정정). 개선 요청을 받았다는 이유로 엔진·평가 규칙·상태 화면을 늘리지 않는다. 실제로 틀리거나 어렵거나 누락된 설명을 찾아 고치고, 운영에서 사용자가 읽는 내용의 전후 차이를 확인한다. 실행 횟수·검사 통과 수·문서화는 보조 근거이며 개선 성과를 대신하지 않는다. 필요한 자동화는 확인된 반복 문제를 해결하는 수단으로만 만든다.
- 기업 내용과 화면 전달을 함께 개선한다(2026-11-03 사용자 재확인). 사업·고객·수익 구조·확인할 점의 사실과 쉬운 설명을 검수하고, 같은 종목에서 용어·질문·실제 답·복귀까지 확인한다. 이미 있는 설명도 누락·반복·출처·문맥을 다시 살피며, 생성 성공이나 화면 클릭 성공만으로 전체 개선을 완료 처리하지 않는다.
- 초보자의 자립을 돕는다(2026-11-02 사용자 확정). 주비를 쓰며 용어와 사건을 이해하고 자신의 투자와 연결해, 점차 스스로 자료를 읽고 판단할 수 있게 돕는다. 미방문 자체를 학습 완료나 성공으로 간주하지 않는다. 이해 부족·정보 누락 때문에 떠난 경우와 충분히 익혀 이용 필요가 줄어든 경우를 실제 사용자 확인으로 구분한다.
- 모르는 용어를 다른 모르는 용어로 설명하지 않는다(2026-11-02 사용자 재확인). ETF·기초지수·지수 이름과 약어 등은 본문에서 뜻·예시·출처를 바로 열고 읽던 위치로 돌아올 수 있어야 한다. 토스와 같은 경쟁 서비스와 비교할 때도 설명 존재·클릭 수만으로 초보자의 이해나 경쟁 우위를 주장하지 않는다.
- 첫 질문·후속 질문·접힌 추가 질문의 실제 답변까지 읽기 검수한다. 정확성·쉬운 말·문맥·반복·다음 확인의 쓸모를 보고, AI 작성 여부를 단어만으로 판정하지 않는다. 질문 수나 탐색 깊이를 늘리는 일을 궁금증 해소로 대신하지 않는다.
- 초보자가 ‘이게 뭐예요? 왜 알아야 해요? 내 주식에 어떤 영향을 줄 수 있어요?’에 답을 얻을 수 있어야 한다.
- 첫 화면에는 지금 중요한 내용을 간결하게 보여준다. 궁금한 내용을 누르면 영향 경로, 관련 정보, 기록으로 자연스럽게 이어지도록 한다.
- 발표 전에는 일정과 알아둘 점, 발표 후에는 확인된 결과와 의미, 이후에는 달라진 상황을 연결한다. 다시 방문했을 때 새롭게 확인할 내용이 있어야 한다.
- 체류시간과 재방문율을 함께 살피고, 설명을 이해했는지와 필요한 정보를 찾았는지도 확인한다. 기능을 추가할 때 이 경험에 어떤 도움이 되는지 설명할 수 있어야 한다.
- 이 방향은 FOMC에 한정하지 않고 경제지표·실적·정책·뉴스 등 모든 이벤트와 서비스 전반에 적용한다. 각 유형의 실제 제공 여부는 아래 적용 범위와 구분한다.

## 핵심 가치
세상의 변화가 내 투자와 어떻게 연결되는지 풀어주는 주식비서.

사용자가 뉴스 제목이나 약어를 이미 안다고 가정하지 않는다. 읽고 나서 사건의 뜻과 영향이 전달되는 과정을 이해하고, 무엇을 더 살펴봐야 하는지 알 수 있어야 한다.

## 신뢰와 지속 개선의 우선순위 (2026-11-01 사용자 확정)
- 틀린 설명, 다른 회사·기간의 사실 혼용, 맥락 없이 반복되는 질문은 서비스 이탈을 만드는 핵심 제품 결함이다. 화면 로딩·버튼 동작·설명 존재만으로 완료라고 판단하지 않는다.
- 사용자가 묻기 전에 중요한 변화를 챙기되, 관찰된 사실·확인된 이유·가능한 영향·아직 모르는 부분을 구분한다. 개인과의 연결은 확인된 정보와 허용된 처리 범위에서 제공한다.
- 회사 이름만 바꾸어도 그대로 성립하는 문장을 회사별 분석처럼 제시하지 않는다. 일반 개념은 필요한 맥락에서 명시적으로 제공하고, 반복 문구를 무작위로 바꾸는 것을 개선으로 세지 않는다.
- 질문은 궁금증을 해결하는 실제 답으로 이어져야 한다. 클릭 수·체류시간·질문 수 자체를 품질 목표로 삼지 않는다. 사용자가 새롭게 이해했는지, 필요한 정보를 찾았는지, 다시 찾을 이유가 있는지를 평가한다.
- 친근함을 만들려고 모든 제목을 ‘~일까요?’로 바꾸지 않는다. 일반 자료는 ‘매출과 이익의 차이’처럼 내용을 직접 밝힌다. 실제 회사의 결과를 전제하는 질문은 해당 사실과 근거가 있을 때만 쓴다. 가정과 과거 결과의 시제를 섞거나 사용자가 정답을 맞혀야 하는 듯한 반문을 피한다. 특정 말끝만으로 AI 작성 여부나 품질을 단정하지 않는다.
- 근거 부족을 숨기지 않되, 누락 안내를 늘리는 것을 해결로 간주하지 않는다. 출처 확보·발행사 식별·설명 생성·근거 검증을 보강해 실제 설명 제공 범위를 넓힌다.
- 별도 개선 서비스는 발견 → 개선안 → 검증 → 반영의 이력을 유지한다. 평가 기준과 엔진도 버전 관리하며, 동일 표본 및 새로운 검증 사례에서 회귀를 확인한다.
- 정확성 실패는 높은 디자인·문장 점수로 상쇄할 수 없다. 자동 탐지, 전문가 판단, 실제 사용자 행동 측정을 구분하며 미검증 영역에 합격 점수를 부여하지 않는다.
- 이 원칙의 기록은 구현 완료나 운영 반영을 뜻하지 않는다. 실제 적용 범위·검사 결과·남은 작업을 별도로 보고한다.

## 공통 구성
1. **무슨 말인가요?** 용어의 뜻을 생활 언어 한두 문장으로 설명한다.
2. **무슨 일이 있었나요?** 확인된 발표 결과와 기준 시점을 보여준다. 예정/결과 확인 중/실제 결과를 구분한다.
3. **왜 그런가요?** 발표 주체가 밝힌 이유가 있을 때 출처와 함께 설명한다. 확인되지 않은 동기를 만들어내지 않는다.
4. **어디로 이어지나요?** 사건 → 금리·환율·원자재·수요 같은 중간 변화 → 기업의 비용·매출·투자 → 실적 기대와 주식 평가의 연결 중 관련 있는 경로를 보여준다.
5. **내 투자에서는 무엇을 보나요?** 확인된 보유 종목·시장·업종 정보에 따라 점검할 항목을 연결한다. 단지 주식을 보유했다는 이유로 모든 사건의 직접 피해·수혜 종목이라고 단정하지 않는다.
6. **달라질 조건은 무엇인가요?** 시장의 사전 예상, 반대 방향의 효과, 기업별 차이, 시간차를 짧게 설명한다.

## 설명의 깊이
- 브리핑/리포트 첫 화면: 용어 한 줄 + 실제 핵심 + 의미 요약.
- 상세: 단계별 연결 + 생활 속 예시 + 달라질 조건 + 출처.
- 모든 설명을 첫 화면에 펼치지 않는다. 더 알고 싶은 사용자가 한 번 눌러 이어서 읽도록 한다.
- 실제 발표·종목에서 생긴 궁금증을 용어·영향 경로·확인할 점으로 풀어준다. 설명을 읽는 데 퀴즈나 문장 작성이 필요하지 않다. 필요한 내용은 선택적으로 메모한다.
- 약어를 다른 약어로 설명하지 않는다. 예: EPS → ‘이익을 주식 한 주 기준으로 나타낸 값’.

## 예시와 사실
- 가상의 카페 회사, 가계 지출 등은 이해를 돕는 예시라고 표시한다.
- ‘금리를 올리면/내리면/그대로 두면’은 학습용 상황 선택이다. 버튼을 눌러도 실제 발표 결과가 바뀌지 않는다.
- ‘물가가 둔화했다’는 사실과 ‘금리 부담이 완화될 수 있다’는 해석을 분리한다.
- 날씨 → 수급 → 원자재 가격 → 기업 이익처럼 멀리 이어지는 설명은 중간 단계의 근거를 생략하지 않는다. 연결이 확인되지 않으면 직접 관련성을 주장하지 않는다.
- 실제 주가가 움직였다는 사실만으로 그 사건이 원인이었다고 서술하지 않는다.

## 현재 적용 범위
- 경제 일정의 FOMC·CPI·PCE·미국 고용·한국은행·기업 실적·휴장일, 총 7개 유형에 공통 뜻풀이/영향 경로/생활 예시/조건을 제공한다.
- `economicEducation.ts`가 유형별 설명, `EventLearning.tsx`가 공통 표현을 담당한다.
- 뉴스·관세·정책·원자재·재해 등 새 콘텐츠에도 위 원칙을 적용할 수 있다. 이 문서 작성만으로 해당 데이터 수집이나 사건별 맞춤 분석이 구현된 것은 아니다.
- 국내 실적, 경제지표 예상치 등 데이터 공급 범위는 `ECONOMIC_BRIEFING.md`를 따른다.
- 리포트에서 금리·물가·환율·실적의 배경 해설을 제공한다. `marketGuides.ts`가 설명과 공식 출처를 관리한다. 실제 뉴스마다 인과관계를 자동 분석하는 기능과 구분한다. 커피 사례·설명 연습 과제는 제공하지 않는다. 사용자가 저장한 용어의 선택 복습은 위 별도 흐름으로 제공한다.
- 기업 연결은 공식 사업 자료를 확인한 5개 회사의 지원 주제부터 제공한다. 사업 사실·자료 기준 기간·출처와 편집한 점검 경로를 구분하고, 이번 발표의 실제 영향이 확정됐다고 표현하지 않는다. 미지원 기업·주제의 연결은 미확인으로 표시하며 샘플은 실제 보유로 취급하지 않는다.
- 로그인 메모는 현재 브라우저에 저장하며 로그아웃·다른 계정 전환 때 제거한다. 같은 탭의 메뉴 왕복 초안은 유지하되 새로고침 전에는 저장이 필요하다. 비로그인 메모는 새로고침·로그인 시 삭제됨을 별도로 안내한다. 기기 간 동기화는 제공하지 않는다. 해설 열기·저장 이벤트에 작성한 글·보유 정보를 포함하지 않는다.

## 연결 탐색 원칙 (2026-10-10)
- 종목·뉴스·일정·리포트·내 투자 전반에서 설명 다음에 맥락에 맞는 질문을 제시한다. 사용자가 검색어를 만들지 않아도 용어 → 영향 경로 → 산업 → 관련 기업 → 비교 기준으로 이어갈 수 있게 한다.
- 질문을 읽은 뒤에도 이전 설명과 처음 질문으로 돌아갈 수 있어야 한다. 체류시간은 이해와 필요한 정보 발견이 쌓인 결과로 평가한다.
- ‘대장주’는 시가총액·제품 점유율·주가 흐름의 기준을 구분한다. 전체 비교 자료와 기준 시점이 없으면 1위를 만들지 않는다. 대표 기업 예시는 사업 역할·선정 근거를 밝힌다.
- 배경 해설 열기에는 AI 분석 횟수를 사용하지 않는다. 제목 기반 배경 연결을 기사 본문 요약이나 당일 변동 원인 분석으로 표시하지 않는다.
- 첫 적용: 기존 4개 경제 해설과 AI 투자·반도체 역할·대장주 판단 기준·기업 비교를 공통 탐색으로 연결. 직접 사업 연결은 확인한 기업만 제공하며 전 업종의 대표 기업·실시간 순위는 아직 제공하지 않는다. 내부 종목 상세는 같은 창에서 열고, 뒤로 가면 읽던 설명으로 돌아갈 수 있어야 한다(2026-10-11 사용자 정정). 출처 원문 링크와 사용자가 직접 요청한 새 탭 열기는 별도로 지원한다.
- 산업 탐색 확대: 주요 산업 11개와 세부 분야 10개, 총 21개 분류에 공통 화면을 적용한다. 사업 근거를 확인한 기업 36개와 설명 71개를 연결한다. 대표 기업·질문·산업별 전달 과정·다음 확인 항목·이어지는 산업을 자료로 관리하며 반도체 전용 화면 분기를 사용하지 않는다. 상세 범위와 대표 종목은 `docs/INDUSTRY_EXPLORATION.md`를 따른다.
- 기업의 여러 사업을 함께 표시할 수 있다. 미등록 종목은 제공된 업종 정보로 연결하고 그 기준을 밝히며, 정보가 없으면 미확인 상태와 산업 목록을 보여준다. 모든 상장사의 세부 사업·실시간 순위까지 확인했다는 의미는 아니다. 산업별 대표 기업은 사업 설명의 출발점이며 시가총액·점유율 1위를 뜻하지 않는다.

- 종목 연결 확대(2026-10-11): 미국145·한국158개 출처별 업종을 추가했다. 21개 독립 산업 이야기·그림과 303개 업종 분류를 구분하며, 모든 산업을 동일한 깊이로 설명하거나 실시간 대장주를 검증했다고 표현하지 않는다. 공급자 충돌·변경된 종목 코드·상품/기업 구분·상장폐지 이력을 보존한다. 수치와 분모는 `docs/INDUSTRY_EXPLORATION.md` 및 커버리지 보고서를 따른다.

## 기업 설명은 궁금증에 답해야 한다 (2026-10-11)
- 사용자가 제품 검토 중 “그래서 이 회사는 어떤 회사야?”라고 묻는다면 화면이 실제 이용자의 궁금증을 해결하는지부터 점검한다. 대화에서만 답하고 제품의 빈 설명을 그대로 두지 않는다.
- “어떤 회사인가요?”라는 제목에는 실제 하는 일과 쓰임이 답으로 나와야 한다. 업종 분류·출처 이름은 사업 설명을 대신할 수 없다.
- 첫 문장은 무엇을 하는지 쉽게 설명하고, 쓰임의 예 → 고객과 필요 → 돈 버는 방식 → 회사별 후속 질문 → 투자에서 확인할 점으로 이어진다. 가상 예시와 실제 계약·고객 사실은 구분한다.
- 근거가 없는 고객·제품·수익 구조는 업종명에서 만들어내지 않는다. 상세 자료가 없으면 확인된 제품이나 사업 요약을 재사용하며, 분류만 있는 화면은 “업종·종목 정보”로 표시해 설명을 제공한 것처럼 보이지 않게 한다.
- 검수 기준에 답변의 내용도 포함한다. 화면 진입·버튼 동작·분류율만으로 회사 이해가 해결됐다고 판단하지 않는다.
- 사용자가 언급한 누락 종목은 전반적 결함을 발견한 사례다. 그 종목만 고치는 방식으로 작업 범위를 축소하지 않는다. 지원 종목 전체와 화면에 노출되는 기업 전체를 분모로 삼아 상세 설명·사업 요약·제품 목록만 있음·설명 없음의 범위를 각각 집계한다.
- 신규 설명 확장은 수집 → 종목 일치 확인 → 한국어 사업 해설 → 근거 검증 → 저장·갱신 → 화면 제공을 공통으로 처리해야 한다. 대표 종목 몇 개의 검수 통과를 서비스 전체의 완료로 보고하지 않는다.

## 시장 관찰은 보유 여부와 독립한다 (2026-10-15)
- 사용자가 든 반도체 하락·서킷브레이커는 지속적인 시장 관찰 체계가 필요한 사례다. 해당 산업·사건 하나에만 대응하는 기능으로 범위를 좁히지 않는다.
- 중요한 시장 변화의 발견·설명·후속 기록을 공통으로 제공하고, 확인된 보유 종목과의 관계는 추가로 설명한다. 종목이 없어도 기본 정보에 접근할 수 있어야 한다.
- 가격 관찰, 공식 조치, 확인된 발표 수치, 기사에서 찾은 소식을 구분한다. 큰 하락률로 거래 중단 발동을 추정하거나 기사 제목에서 인과관계를 만들지 않는다.
- 정기 수집 범위·주기·확인 시각·자료 누락을 공개한다. 산업 분류·검색 성공을 전 세계 모든 기업의 실시간 감시로 설명하지 않는다.
- 공통 시장 관찰의 실제 공급 범위와 운영 적용 상태는 `docs/MARKET_WATCH.md`를 따른다.

## 화면 강조와 포커스 기준 (2026-10-10)
- 사용자 피드백: 보조 버튼에 나타나는 두꺼운 파란 테두리와 과한 둥근 상자는 큰 디자인 결함으로 본다. 브라우저 기본 포커스가 의도하지 않은 시각적 강조로 남지 않게 한다.
- 화면 진입 시 보조 버튼을 자동 강조하지 않는다. 모달의 첫 읽기 위치는 제목 등 맥락을 설명하는 요소로 지정하고, 키보드 탐색은 계속 지원한다.
- 마우스 클릭과 키보드 탐색 표시를 구분한다. 포인터 사용에는 불필요한 외곽선을 표시하지 않고, 키보드 focus-visible은 얇은 중립색으로 보인다. 접근성 표시를 모두 없애지는 않는다.
- Typesafe 캡처의 흰색·회색 바탕, 얇은 구분선, 명확한 제목 크기, 여백을 종목 상세의 디자인 참고로 적용한다. 첫 화면·클릭 후·키보드·모바일·다크 모드의 실제 상태를 확인한다.

## 재무 수치 제공 범위 (2026-10-23, 운영 적용)
- 현재 상세의 기업 재무 수치(PER·EPS·시가총액·배당수익률 등)는 제공하지 않는다. 공급되지 않는 숫자를 빈 지표 묶음으로 노출하지 않는다.
- 회사가 하는 일, 산업과 기업 연결, 시세·거래량·뉴스 및 재무 개념 설명은 유지한다. 가상 수치는 실제 회사 실적과 분리해 표시한다.
- 최신 재무수치가 없는 AI 답변은 이를 전제로 설명하며 현재 저평가·배당 상태를 수치로 꾸며내지 않는다.
- 검증된 공급원·기준일·갱신·결측 처리까지 갖추기 전에는 숫자 표를 재도입하지 않는다. 운영 적용 상태는 docs/TRUST_FIXES_RELEASE.md를 따른다.
