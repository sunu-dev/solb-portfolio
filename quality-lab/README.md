# 주비 개선 작업실

## 기업 내용과 화면 설명 공동 검수 0.6.0 (2026-11-03)

- 기업 설명이 ‘상세’로 등록돼 있어도 실제 화면에서 사업 요약·고객·수익 구조·점검 내용을 읽는다. 접힌 고객/수익 설명을 열고 원래 상태로 복구한다. 정적 회사의 API가 요약만 제공하는 경우도 있으므로 API 필드 부재를 곧바로 화면 누락으로 판정하지 않는다.
- 기존 내용의 누락·출처 부재·항목 간 같은 답 반복·긴/추상적인 문장을 개선 단서로 남긴다. 반복·문장 길이는 의미 검토 요청이며 사실 오류나 AI 작성 여부의 판정이 아니다. 원문 대조는 별도다.
- `company-content-review`는 기존 기업 설명의 편집 검수 과제다. 누락 설명 생성 요청과 구분하고, 이 과제만으로 모델 생성·공개·배포를 실행하지 않는다.
- 종목별 `explanationStatus`에서 기업/상품 내용과 화면 설명·질문·용어 상태를 함께 표시한다. 한쪽이 미수집이면 미확인, 결함이 있으면 보완 필요, 전달이 관측돼도 원문·문맥 검수 대기로 남긴다. 사용자 이해도는 측정하지 않았다고 표시한다.
- 기업 설명 전달 확인은 같은 공개 버전의 실제 운영 수집이어야 하며, 표시 본문을 읽은 기록과 알려진 내용 결함 부재가 필요하다. 후보·가져온 기록·API의 ‘상세’ 표시만으로 닫지 않는다. 이 전달 확인은 전체 품질 검수 완료와 별개다.
- 엔진0.6.0/수집기0.6.0/루브릭v3. 과거 표본10개의 **규칙 재평가** `ef8515d15a27ce576c65`를 저장했다. 당시 없는 본문·화면 관측은 미확인으로 남긴다. 실제 신규 운영 순회·내용 재작성·모델 호출·상시 실행은 수행하지 않았다. 품질 작업실 전체66검사 통과.

- ETF·기초지수·NYSE 반도체지수의 뜻 연결을 점검하고, 실제 용어 창의 열기·정의·닫기를 기록한다. 같은 검사를 후속 답변에도 적용한다.
- 접힌 질문을 포함해 최대 7개 시작 질문에서 각각 다음 답변까지 수집한다. 답변 원문·다음 질문·용어 설명을 지문에 포함한다. 빈 답, 다른 질문의 같은 답, 방금 읽은 답으로의 순환, 추상적인 문구는 검토 과제로 남는다.

- 루브릭 v2는 처음 보는 용어의 뜻과 예시를 문맥 안에서 확인할 수 있는지 평가한다. 기존 점수는 새 기준의 점수로 재사용하지 않는다. 이전 수집에 새 관측 필드가 없으면 미평가로 표시한다.
- 탐색 과제는 실제 운영의 후속 수집에서 해당 전달 검사가 충족돼야 완료로 기록한다. 정적 렌더 검사나 미배포 후보는 운영 전달 완료가 아니다. 재발하면 다시 연다.
- 이 코드를 추가한 것이 상시 실행을 켰다는 뜻은 아니다. 기존 장애 보류·부하/예산 제한과 공개 승인 정책을 유지한다. 전체 종목 의미 검수·24시간 운영·사용자 학습 성과는 미완료다.

운영 앱과 별도로 실행하는 품질 개선 서비스의 첫 버전이다. 사용자 화면에서 문제를 발견하고, 근거와 개선 과제를 남기며, 변경 전후와 평가 기준의 변화를 추적한다.

전체 방향은 [지속 개선 순환 설계](../docs/JOOBI_CONTINUOUS_IMPROVEMENT_CYCLE.md)에 정리했다. 0.2.0은 회사 설명 누락을 운영 수집 큐로 전달하고, 검수·공개·실제 화면 전달까지 추적한다. 첫 사건 설명은 여전히 개발용 화면에만 연결되어 있다. 두 경로를 혼동하지 않는다.

## 제품 방향

주비는 개인 주식비서다. 정확한 사실에서 회사·사건·의미·내 투자와의 관계를 이해하게 해야 한다. 출처 없는 설명, 회사와 무관한 반복 질문, 자금 조달을 수주로 읽는 오류는 신뢰 결함이다. 높은 디자인 점수로 상쇄하지 않는다.

## 독립 실행

Node 20 이상. 이 폴더만 별도 저장소나 서버로 옮길 수 있다. 운영 Next.js 빌드, Supabase, 회원 DB, 서비스의 Gemini 키에 의존하지 않는다.

```sh
cd quality-lab
npm ci
npm test
node src/cli.mjs import ../artifacts/free-quota-company-context-20261101/random-review ../artifacts/free-quota-company-context-20261101/random-ticker-selection.json
npm start
```

Chrome이 설치된 환경에서 사용한다. 화면 수집은 새로운 비로그인 브라우저 컨텍스트를 사용한다. 실행 화면은 `http://127.0.0.1:4318`. 기본 저장소는 `data/`이며 `JOOBI_LAB_DATA`로 분리할 수 있다. 수집 대상은 기본 joobi.kr만 허용하고 후보 배포 주소는 실행 전에 `JOOBI_LAB_TARGETS`에 정확한 origin을 추가한다.

## 현재 동작

- 고정 표본의 회사 이해·거래일 브리핑·배우기 화면과 공개 응답 일부를 수집한다. 새 수집은 질문 → 설명 → 질문 목록 복귀도 확인한다.
- 반복 질문, 사업 설명 누락/빈약함, 일반 점검 문구, 알려진 계약 문맥 오류, 화면 실패 등을 탐지하고 공통 개선 과제로 묶는다.
- 원문 문장·화면·콘텐츠 지문·표본·평가 기준·엔진 버전을 기록한다. 평가를 붙여도 이전 결과를 덮어쓰지 않는다.
- 전문가/모델의 축별 채점에는 실제 화면 근거가 필요하다. 없는 인용·바뀐 내용의 채점은 거절한다. 모델 점수는 독립 검수 전 제안이다.
- 같은 표본·기준·엔진의 전후를 비교한다. 치명적 문맥 오류나 사실 검증 실패는 평균 점수와 관계없이 차단한다. 미검증은 통과가 아니다.
- 작업실에서 하루 1회 반복 수집을 켤 수 있다. 프로세스가 실행 중일 때만 작동하며 기본은 꺼짐이다. 중복 수집은 프로세스 간 잠금으로 막는다. 비정상 종료 후 남은 잠금은 PID를 확인한 운영자가 정리한다.

## 구현하지 않은 범위

이 버전은 자동 개선의 발견·증거·과제·회사 설명 전달 검증을 제공한다. 전체 사실의 자동 검증, 의미를 이해하는 모델 심사, 코드 수정 생성·PR·자동 배포, 사용자 이해도/재방문 효과 측정, 24시간 상시 호스팅은 구현 완료가 아니다. 현재 개선안은 실행 가능한 검수 조건을 포함한 규칙 기반 제안이며 제품 수정 완료가 아니다.

## 다음 엔진 단계

1. **사건·주장 구조화:** 회사·기간·사건 종류·진행 단계·핵심 주장·출처 문단을 연결. 계약 체결/종료, 자금 조달/판매를 구분한다.
2. **개선 후보 생성:** 자료 부족은 수집 과제, 맥락 오류는 연결 알고리즘 수정, UX 문제는 화면 후보로 분리. 원문 수집 → 설명 생성 → 출처 대조를 연결한다.
3. **독립 검증:** 생성기와 분리된 판정, 알려진 오류 회귀 세트, 개발에 쓰지 않은 표본, 사람이 확인한 기준 답변을 사용한다. 모델이 자료에서 읽은 지시문은 실행하지 않는다.
4. **승격:** 정확성 실패 0, 미검증 해소, 같은 사례의 개선, 새 사례 회귀 없음, 모바일·접근성·사용자 이해 검증을 충족한 후보만 릴리스한다. 승인 기록과 롤백 대상이 있어야 한다.
5. **엔진 교정:** 사람의 정정으로 회귀 사례를 추가하고 탐지 오탐·누락·심사자 불일치를 비교한다. 채점 기준을 바꿔 점수가 오른 경우는 제품 개선으로 표시하지 않는다.

## 첫 설명 전달 경로 (2026-11-01)

`context-packet.mjs`는 공식 SEC 공시 HTML과 구조화한 초안을 받아 발행사·티커·날짜·계약 상대방·종료 단계·인용문 위치를 검사한다. 원문 해시, 초안 해시, 답변별 근거, 만료일을 묶어 불변 후보를 `data/contexts/`에 저장한다. 주비용 JSON에는 전체 공시/인용문이 들어가지 않는다. 이 파일럿 어댑터는 신주 매각 계약 종료만 지원하며, 초안 작성은 자동화하지 않았다.

```sh
node src/cli.mjs export-preview DRAFT.json SOURCE.html /path/to/joobi/src/data/stock-context-preview.json
```

작업실의 **개선안 검토**에서 근거 링크와 질문·답을 볼 수 있다. 주비는 `NODE_ENV=development`와 `JOOBI_CONTEXT_PREVIEW=true`를 모두 만족할 때만 이를 읽는다. 운영 빌드는 후보를 제공하지 않는다. 정확한 종목, 최근 기사, 계약 상대방·사건 단계가 맞을 때만 표시한다. 기존 기업 설명의 편집승인/공개 경로를 우회하지 않는다.

원문에 문장이 있다는 검사, SHA-256 무결성, 같은 발행사 확인은 **출처 진위의 독립 확인·번역/해석 검수·주가 인과 검증을 대신하지 않는다**. 현재 `semanticReview=pending`, `publication=blocked`이며 초안을 승인된 설명으로 바꾸는 명령은 없다. 외부 문서에서 발견한 지시문을 실행하지 않는다.

## UI 계획과 점검

- 흰색 `#ffffff`, 본문 `#191f28`, 보조 글 `#596575`, 구분선 `#e6e9ed`, 선택 노랑 `#fff0a8`, 오류 `#a72d34`를 쓴다. 오류는 색과 문구를 함께 표시한다.
- 시스템 한국어 글꼴(Apple SD Gothic Neo/Noto Sans KR), 본문 16px, 제목 28px. 숫자는 표에서 정렬한다.
- 화면의 중심은 점수 장식이 아니라 **문제 문장과 실제 화면의 대조**다. 왼쪽 종목 목록, 오른쪽 근거·평가, 별도 개선 과제/전후 비교. 모바일은 목록 다음 근거 순서로 쌓는다.
- 총점은 참고 평가로 표시한다. 별도의 신뢰 차단 상태를 항상 노출한다. 빈 상태·미채점·미수집은 0점이나 합격으로 대체하지 않는다.
- 일반 대시보드의 큰 숫자 카드 대신 문맥 오류 한 건을 먼저 보여주도록 계획을 수정했다. 실제 사용자 행동 효과는 측정 전 수치로 만들지 않는다.

## 채점·비교 명령

```sh
node src/cli.mjs review RUN_ID assessment.json
node src/cli.mjs compare BEFORE_ID AFTER_ID
node src/cli.mjs capture RUN_ID
```

`assessment.json`은 symbol, rubricHash, contentHash, evidenceHash, kind(expert/model), reviewer, axes의 score/reason/evidence, trust(status/reason/evidence)를 가진 배열이다. evidence 인용은 실제 수집 문장과 일치해야 한다. 화면 지문도 함께 검증해 문장은 같고 디자인만 바뀐 경우 이전 채점을 재사용하지 않는다. V0는 원문 검증 체인이 연결되지 않아 trust의 verified 입력을 거절한다. unreviewed/failed와 미검증 범위를 기록한다.

## 비용과 개인정보

이 도구 자체는 외부 모델 API를 호출하지 않는다. 수집 대상 사이트의 공개 조회에는 기존 서비스의 네트워크·캐시 비용이 발생할 수 있다. 회원 로그인·계좌·메모·암호화 키를 가져오지 않는다. 캡처 이미지는 운영자 로컬에 저장하며 인터넷에 공개하는 서버 구성은 제공하지 않는다. 운영 서비스의 하루 3회 AI 한도 변경은 별도 작업이다.

## 개선 처리 연결 0.2.0 (2026-11-01)

- 공개 화면의 설명 누락을 종목·문제 유형별 작업 하나로 유지한다. 재검사는 관찰 이력을 추가하며 진행 상태·예산·재시도 횟수를 초기화하지 않는다. 수집 실패는 콘텐츠 생성 요청으로 보내지 않는다.
- `plan`은 종목·검사 버전·지문만 담은 요청을 만든다. 별도 운영 명령 `scripts/company-business-engine.cjs dispatch-plan`이 서비스 전용 RPC로 기존 회사 작업의 우선순위를 올린다. 작업실에는 운영 DB 자격 증명을 주지 않는다.
- `receipt`는 전달 결과만 기록한다. `progress`는 출처 확보, 초안, 모델 검수, 편집 검수, 공개를 각각 기록한다. 공개되지 않은 설명을 완료로 표시하지 않는다.
- 실제 화면을 나중에 수집해 공개 버전 일치·출처·상세 설명·탐색 성공을 확인해야 `운영 화면 반영 확인`이 된다. 이는 전달 검증이며 모든 사실의 자동 의미 검수나 사용자 만족도 입증은 아니다. 누락이 재발하면 작업을 다시 연다.
- 회사 엔진은 거절 사유를 버리지 않고 초안 수정에 활용한다. 수정 최대 2회, 기존 공용 모델 예산 유지, 편집 검수 없는 자동 공개 금지. 실제 CARG 검토에서 모델이 놓친 의미 오류가 발견되어 편집 검수를 유지했다.
- 국내 공시 인증이 없는 종목은 `국내 공시 연결 필요`로 남는다. 미국 5개 요청이 전달됐다고 5개 설명이 완성된 것으로 세지 않는다.
- 뉴스 조회 실패·불완전 조회도 별도 작업으로 기록한다. 기사 요약·원인 분석·본문 접근 문제를 모두 자동 해결하는 엔진은 아니다.

```sh
node src/cli.mjs plan RUN_ID /absolute/path/repair-manifest.json
# 별도 운영 환경에서 dispatch-plan을 실행한 뒤 생성된 영수증만 가져온다.
node src/cli.mjs receipt /absolute/path/repair-manifest.json /absolute/path/dispatch-receipt.json
node src/cli.mjs progress /absolute/path/repair-manifest.json /absolute/path/progress-receipt.json
node src/cli.mjs capture RUN_ID
```

현재 전달·진행 조회 명령은 운영자가 실행한다. 로컬 반복 수집은 켜고 프로세스를 유지할 때만 작동한다. 24시간 자동 운영·자동 코드 수정·자동 배포가 완료된 것은 아니다.

## 자동 실행 준비 (2026-11-02)

`src/automation.mjs`와 별도 운영 브리지 `../scripts/run-quality-improvement.mjs`가 큐 전달 → 진행 조회 → 제한된 작업 실행 → 진행 반영 → 실제 화면 검사를 이어서 실행한다. 작업실 웹 서버에는 운영 자격 증명이나 공개 승인 권한을 추가하지 않았다.

기본은 관찰 모드다. `automation-policy.example.json`은 비활성·장애 보류 상태이며 그대로 두면 모델 호출이나 운영 DB 쓰기가 없다. 실행 모드에서도 최근 10분 이내 서비스/DB 정상, 같은 통계 기간의 1~15분 I/O 차이, 장치별 빠짐없는 지표와 갱신이 확인된 낮은 파일럿 부하, 확인된 제공자 할당량, 명시적 장애 해제가 모두 필요하다. 순간 IOPS가 낮다고 Disk IO Budget이 회복된 것으로 판단하지 않는다.

```sh
# 운영 쓰기·모델 호출 없이 실행 가능 여부 확인
node scripts/run-quality-improvement.mjs RUN_ID SNAPSHOT.json POLICY.json
# 위 조건을 실제로 충족하고 운영 자격 증명이 구성된 환경에서만 실행
node --env-file=.env.local scripts/run-quality-improvement.mjs RUN_ID SNAPSHOT.json POLICY.json --execute
```

명령은 저장소 루트에서 실행한다. 하루 최대 1~3회 시도, 동시 실행 잠금, 타임아웃 전 시도 예약, 국내 공시 미연결 제외, 일 1회 이하 화면 수집을 적용한다. 동일 작업의 전송·모델 재시도 폭주를 막으며 기존 DB/model 예산도 계속 적용된다. 새 설명 승인·공개·예산 초기화·코드 배포를 호출하는 기능은 없다. workerRelease는 격리된 검증 릴리스 경로와 SHA-256이어야 하며, 각 운영 명령 전에 실행 소스/패키지 지문을 다시 확인한다. 원본 workspace 실행은 거절한다. 실패로 남은 잠금은 PID/실행 상태를 확인한 뒤 운영자가 처리한다.

이번 실제 장애 관측을 입력한 실행 모드는 작업 시작 전에 차단됐다. 정상 운영 E2E, 상시 스케줄러 배포, 무료 제공자 할당량 자동 수집, 독립 의미 검수 및 자동 공개 준비가 모두 끝난 것으로 해석하지 않는다. 상세 출시 조건은 `../docs/AUTOMATION_READINESS_2026-11-02.md`를 따른다.
