# 2026-10-22 - 디자인 운영 배포·시장 소식 복구

## 작업 요약
사용자가 운영 배포와 로컬 시장 소식 API 오류 수정을 요청했다. 이전 운영 선별 소스를 복제한 격리 폴더에 승인된 손그림v2·공통 디자인·계정 삭제 설정 이동·시장 소식 기능을 선별 병합했다. 원본 workspace 전체는 배포하지 않았다.

시장 API503은 연결된 DB의 market_watch_events·market_watch_runs 누락(PGRST205)이 원인이었다. 관련 SQL만 적용하고 실제 수집·저장을 실행해 로컬·운영 API200을 확인했다. 현재 Vercel Hobby의 잦은 cron 제한을 확인해 기존 Supabase pg_cron·pg_net·Vault에 시장10분/산업2시간 작업을 구성했다. 사용자 테이블·요금제는 변경하지 않았다.

최초 빌드에서 외부 의존성 심볼릭 링크가 거부돼 실제 복사로 바꿨다. 최초 원격 빌드에서 산업 분류 원본을 제외한 문제가 발생해 제외 설정을 수정했다. 재배포의 테스트1,629개·타입·Next 빌드 성공 후 joobi.kr을 전환했다. 실패 배포는 운영으로 전환하지 않았다.

운영 READY `dpl_DT8vupUnrCWfup4qhhq4xkgQdWDY`. Chrome에서 홈·리포트·산업 필터,390/320px 가로 넘침·이미지·운영 콘솔을 확인했다. 공개 API200·49개 기록, 인증 없는 수집401. 시장12:00 UTC·산업12:05 UTC의 실제 정기 실행 → HTTP200 → 저장된 발행 시각까지 확인했다.

## 결정사항
- 승인된 디자인과 복구에 필요한 파일만 배포했다.57개 파일 목록·해시·복원용 tgz 및 비교 patch를 보관했다.
- 공개 시장 API는 저장 자료만 읽는다. 방문자 요청으로 수집·생성을 시작하지 않는다.
- 예약 인증값은 기존 운영 값을 Vault에 저장하고 기록·소스에 남기지 않았다. 고정 두 범위·고정 운영 URL만 호출하는 관리자 전용 함수를 쓴다.
- 일부 원천 누락·지연은 화면과 확인 범위 경고로 유지한다. HTTP200을 모든 원천 검증 완료로 표시하지 않는다.
- 계정 삭제를 실제로 실행하지 않았다. 기존 확인 두 단계는 유지했다.
- 영속적인 운영 구성은 docs/MARKET_WATCH.md에 기록했다. 새 사용자 선호·작업 규칙의 auto-memory 승급은 이번 범위에 추가하지 않았다.
